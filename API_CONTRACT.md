# API_CONTRACT — цикл B ServiceBooking

**Назначение.** Точка синхронизации backend- и frontend-разработчика на время цикла. Обе стороны
работают по этому файлу, а не по коду друг друга (`ARCHITECTURE.md` §18, таблица «Точки пересечения BE↔FE»).

**Что здесь есть.** Все эндпоинты, которые цикл B трогает или добавляет. Остальной API описан в
`API_DOCUMENTATION.md` и в этом цикле не меняется. Изменения цикла A уже применены к коду и здесь
не повторяются — этот файл описывает **фактическое состояние на `1c21bca`** и дельту цикла B.

**Источник истины по решениям.** `SPEC.md` цикла B §0 (Q5–Q18) и `ARCHITECTURE.md` (§3 хранилище,
§4 загрузчик, §5 модель, §6 квота, §8 планировщик, §10 rate limiting, §13 формат ошибок, §19 задачи).
Контракт ниже не вводит альтернатив — он фиксирует принятое в терминах запрос/ответ.

**Базовая ревизия.** Ветка `sanitation-cycle`, коммит `1c21bca`. Все ссылки «файл:строки» — по ней.

**Ломающих изменений в цикле ровно четыре** (SPEC §9 п. 7), все помечены **BREAKING** и сведены
в §20. Пятого нет: всё остальное аддитивно.

## 0. Общие соглашения

### 0.1 Сериализация

| Тип C# | JSON | Пример |
|---|---|---|
| Имена свойств | camelCase | `clientNoteId`, `sizeBytes` |
| `enum` | **строка** (`JsonStringEnumConverter`, `Program.cs:48-49`) | `"Confirmed"`, `"TwelveMonths"` |
| `DateOnly` | `"YYYY-MM-DD"` | `"2026-09-01"` |
| `TimeOnly` | `"HH:mm:ss"` | `"10:00:00"` |
| `DateTime` | ISO-8601 UTC | `"2026-09-02T11:04:17.9231Z"` |
| `decimal` | число | `800` |
| `long` (байты) | число | `312845` |

Базовый путь фронта — `/api` (`frontend/src/api/client.ts:5`), токен подставляется интерцептором
(`client.ts:9-13`). Обработка 401 (`client.ts:15-24`) в цикле B **не меняется**.

### 0.2 Формат тел ошибок — граница цикла A, перенесённая без изменений

| Код | Как формируется | Content-Type | Тело | Цикл B |
|---|---|---|---|---|
| 400 | `BadRequest("текст")` | `text/plain; charset=utf-8` | **голая строка** | без изменений; все новые 400 — тоже голые строки |
| 400 | `BadRequest(identityErrors)` | JSON-массив строк | без изменений (`memberError.ts:23-27`) |
| 400 | автовалидация `[ApiController]` | `application/problem+json` | `ValidationProblemDetails` | без изменений |
| 401 | пайплайн JWT | — | пустое | без изменений |
| 402 | `StatusCode(402, "текст")` | `text/plain` | голая строка | без изменений |
| 403 | `Forbid()` | — | **пустое** | без изменений |
| 404 | `NotFound()` / `NotFound("текст")` | — / `text/plain` | пусто / строка | без изменений |
| 409 | `Conflict("текст")` | `text/plain` | голая строка | без изменений |
| **413** | `[RequestSizeLimit]` / Kestrel | — | пустое | появляется на загрузках |
| **429** | rate limiter, `OnRejected` | **`text/plain`** | **голая строка** | **новый код цикла** |
| 500 | необработанное исключение | `application/problem+json` | `ProblemDetails` + `traceId` | без изменений |

`AddProblemDetails()` и `UseStatusCodePages*` **запрещены** — они переписали бы тела 4xx, на которых
стоят мапперы `src/utils/*Error.ts`.

**429 обязан иметь тело.** По умолчанию `RateLimiter` отдаёт пустое, и `uploadError.ts` не отличил бы
его от 403. Поэтому `OnRejected` пишет строку явно (`ARCHITECTURE.md` §10.1).

**Исключение из правила «новые тексты 400 не содержат `captcha`/`name`/`phone`».** Текст
`Phone number must contain 10 to 15 digits.` содержит `phone` и в гостевой записи попадёт в ветку
`bookingError.ts:30` («Укажите имя и телефон»). Проверено: для невалидного номера гостя это корректное
сообщение. Текст оставлен, маппер не правится (`ARCHITECTURE.md` §11.2, §21.5).

### 0.3 Загрузка файлов: общая форма запроса

Все четыре эндпоинта загрузки принимают `multipart/form-data` с **одним** полем `file`:

```
POST /api/... HTTP/1.1
Authorization: Bearer <jwt>
Content-Type: multipart/form-data; boundary=…

--…
Content-Disposition: form-data; name="file"; filename="IMG_2031.HEIC"
Content-Type: application/octet-stream
<байты>
```

`filename` и `Content-Type` части **игнорируются полностью** — ни для решения о приёме, ни для
расширения на диске (US-19 п. 1). Формат определяется по сигнатуре: JPEG, PNG, WEBP.

**Общие коды для всех загрузок:**

| Код | Тело (`text/plain`) | Когда |
|---|---|---|
| 400 | `File is required` | поле `file` отсутствует или пустое |
| 400 | `Image is too large — the limit is 5 MB` | размер тела больше `Uploads:MaxFileBytes` |
| 400 | `Unsupported image type — use JPEG, PNG or WEBP` | сигнатура не распознана (текст **прежний**, был у логотипа) |
| 400 | `File is not a valid image` | сигнатура прошла, декодер не осилил |
| 400 | `Server storage is full — try again later.` | на диске меньше `Storage:MinFreeDiskMb` |
| 401 | пусто | нет токена |
| 403 | пусто | нет прав на целевую сущность |
| 413 | пусто | тело больше `[RequestSizeLimit(5 MB)]` (обрывается до контроллера) |
| **429** | `Too many uploads. Try again in a minute.` | > 10 загрузок в минуту на пользователя |

Лимит частоты — **10 загрузок в минуту на пользователя** (значение зафиксировано архитектором,
US-19 п. 5; ключ конфигурации `Uploads:PerUserPerMinute`). Партиция — по id пользователя, для
анонимов — по IP. Очереди нет: превышение отвечает сразу.

Что происходит с изображением всегда, независимо от эндпоинта и тарифа: ресайз до размера профиля,
применение EXIF-ориентации к пикселям, перекодирование, **полное удаление метаданных** (US-19 п. 3).
Исходный файл не сохраняется.

## 1. `GET /api/masters/clients` — US-07, US-18 · задача T-B4 (+ T-F11) — **BREAKING № 1**

Файл: `ServiceBooking.API/Controllers/MastersController.cs:17-97`.

### 1.1 Текущее поведение

**Доступ:** `[Authorize]` + `CompanyMembership.IsStaffAsync(companyId, userId)` → `403`.
**Query:** `companyId` (`Guid`, обяз.).

**200 OK** — массив объектов двух видов (зарегистрированные клиенты и гости):

```json
[{
  "clientId": "6a9c…", "guestPhone": null,
  "name": "Анна Петрова", "phone": "+79990000000", "email": null,
  "lastVisitDate": "2026-08-30", "totalVisits": 4,
  "notes": ["Красится в 7.1", "Аллергия на аммиак"],
  "bookingSummaries": [{ "date": "2026-08-30", "serviceName": "Стрижка", "status": "Completed" }]
}]
```

`notes` — **массив голых строк** (`.Select(n => n.Note)`, `:51` и `:78`). Ни id, ни автора, ни даты:
`DELETE /api/masters/clients/notes/{id}` реализован, но привязать его в UI не к чему.

### 1.2 Целевое поведение

**`notes` становится массивом объектов. Это ломающее изменение контракта № 1.**

```json
[{
  "clientId": "6a9c…", "guestPhone": null,
  "name": "Анна Петрова", "phone": "79990000000", "email": null,
  "lastVisitDate": "2026-08-30", "totalVisits": 4,
  "notes": [
    {
      "id": "b1c2d3e4-…",
      "note": "Красится в 7.1",
      "createdAt": "2026-08-30T14:12:03.114Z",
      "authorId": "9f8e…",
      "authorName": "Ирина К.",
      "bookingId": "77aa…",
      "bookingDate": "2026-08-30",
      "bookingServiceName": "Окрашивание",
      "canDelete": true,
      "photos": [
        {
          "id": "cc11…",
          "url": "/api/client-notes/photos/cc11…",
          "thumbnailUrl": "/api/client-notes/photos/cc11…/thumb",
          "width": 1600, "height": 1067, "sizeBytes": 312845,
          "createdAt": "2026-08-30T14:12:41.881Z",
          "uploadedByName": "Ирина К.",
          "canDelete": true
        }
      ]
    }
  ],
  "bookingSummaries": [ … без изменений … ]
}]
```

Свойства, которые контракт фиксирует явно:

1. `bookingId`, `bookingDate`, `bookingServiceName` — `null`, если заметка не привязана к визиту.
   `bookingDate`/`bookingServiceName` добавлены сверх US-07 п. 1, потому что US-18 п. 4 требует
   показать, к какому визиту относится фото, — иначе фронту пришлось бы искать визит самому.
2. `canDelete` вычисляется **для вызывающего**: `true`, если он автор заметки **или** владелец этой
   компании (решение Q16). У фото — то же плюс «загрузил это фото» (`ARCHITECTURE.md` §21.3).
3. **`url` и `thumbnailUrl` — пути к API, а НЕ значения для `<img src>`.** Они требуют заголовка
   `Authorization`, которого браузер к `<img>` не добавит. Фронт загружает их через axios как blob
   (`ARCHITECTURE.md` §12.2, задача T-F9). Подставить эти строки прямо в `src` — гарантированный 401.
4. Заметки отсортированы по `createdAt` **убыв.** и **ограничены 50 последними на клиента**
   (`Take(50)`, NFR §9 п. 6). Фото — по `createdAt` возр., максимум 5 по построению.
5. `phone`/`guestPhone` теперь **канонические** (только цифры) — см. BREAKING № 4, §12.

| Что | Было | Стало |

## 2. `POST` / `DELETE /api/masters/clients/notes` — US-07 · задача T-B4

### 2.1 `POST /api/masters/clients/notes`

**Было:** тело `{ companyId, clientId?, guestPhone?, note }`, ответ `200 { "id": "…" }`,
проверка — членство **любой роли** (`:106-107`).

**Стало:**

| Что | Изменение |
|---|---|
| Тело | **+ `bookingId` (`Guid?`, опционально)** — заполняется, когда заметка создаётся из панели под записью (US-17 п. 4) |
| `guestPhone` | нормализуется сервером до записи (BREAKING № 4) |
| Проверка прав | `CompanyMembership.IsStaffAsync` вместо «членство любой роли» — приводится к конвенции, `Client`-участник больше не может засеивать заметки |
| Ответ | `201 Created` + **полный `ClientNoteDto`** вместо `200 { id }` — фронту нужен объект целиком, чтобы сразу отрисовать заметку и прикреплять к ней фото |
| Новые коды | `400` `Note text is required.` (пустая заметка); `400` `Note must be 2000 characters or fewer.`; `400` `Booking does not belong to this company.` при чужом `bookingId` |

Смена `200 { id }` → `201 ClientNoteDto` **не входит в четыре ломающих**: единственный потребитель
(`masters.ts:18-19`) ответ не читает вовсе, а расширение тела аддитивно.

### 2.2 `DELETE /api/masters/clients/notes/{id}`

**Было:** `n.MasterId == userId` → иначе `404` (`:132-133`).

**Стало** (решение Q16 + правило `ARCHITECTURE.md` §21.4):

```
401  аноним
404  заметки нет ИЛИ вызывающий не персонал компании этой заметки   ← межарендная изоляция
403  вызывающий персонал этой компании, но не автор и не CompanyOwner
204  успех — заметка, её фото (каскад) и файлы с диска удалены
```

Порядок удаления: строки → commit → файлы (`ARCHITECTURE.md` §1.4). Не удалившиеся файлы подберёт
фоновая уборка сирот.

## 4. `POST /api/client-notes/{noteId}/photos` — US-17, US-19 · задача T-B5 · **НОВЫЙ**

Новый контроллер `ClientNotePhotosController`, `[Route("api/client-notes")]`. Все четыре маршрута фото
живут под одним префиксом, потому что путь раздачи зафиксирован SPEC US-19 п. 4 дословно.

**Доступ:** `[Authorize]`, `[EnableRateLimiting("uploads")]`, `[RequestSizeLimit(5 MB)]`.
Вызывающий обязан быть `Master`/`CompanyOwner` компании, которой принадлежит заметка.

**Запрос:** `multipart/form-data`, поле `file` (§0.3).

**201 Created** — `ClientNotePhotoDto` (форма — §1.2) + заголовок `Location: /api/client-notes/photos/{id}`.

**200 OK** — тот же DTO, если этот же файл уже приложен к этой заметке (повторная отправка формы,
двойной клик, ретрай сети). Квота при этом **не расходуется повторно** — дедупликация по хешу
обработанных байтов (`ARCHITECTURE.md` §6.3, NFR §9 п. 2). Фронт различать 200 и 201 не обязан.

**Коды:**

| Код | Тело (`text/plain`) | Когда |
|---|---|---|
| 400 | общие из §0.3 | размер, формат, битый файл, нет места |
| 400 | `This note already has 5 photos.` | шестое фото (US-17 п. 6, `MC-1xz`) |
| 400 | `Photo storage quota exceeded: 98 of 100 MB used. Upgrade the plan for more space.` | квота компании исчерпана. Числа — **переменная часть**, фронт достаёт их регуляркой и обязан корректно отработать их отсутствие |
| 401 | пусто | аноним |
| 403 | пусто | персонал **другой** компании — здесь именно 403, а не 404: `noteId` вызывающему уже известен из URL, скрывать нечего, а 403 читается однозначно |
| 404 | пусто | заметки с таким `noteId` нет |
| 413 / 429 | см. §0.3 | |

## 12. Канонизация телефона — US-26 · задача T-B14 — **BREAKING № 4**

**Правило.** Из строки удаляются все нецифровые символы. Российский номер из 11 цифр, начинающийся
с `8`, приводится к `7…`; номер из 10 цифр, начинающийся с `9`, дополняется до `7XXXXXXXXXX`;
прочие сохраняются как последовательность цифр. После нормализации — от 10 до 15 цифр (E.164),
иначе `400`.

**Клиент может продолжать присылать любой формат.** Меняется то, что **возвращается**: везде канон.

### 12.1 Точки применения

| Эндпоинт | Что нормализуется | Новый код |
|---|---|---|
| `POST /api/auth/register` | `phone` перед созданием | `400` `Phone number must contain 10 to 15 digits.` |
| `POST /api/auth/login` | `phone` перед поиском | — (неверный номер по-прежнему `401`) |
| `POST /api/companies/{id}/members` | `phone` для поиска существующего **и** для автосоздания | `400` тот же |
| `POST /api/profile/change-phone` | `newPhone` перед `SetUserNameAsync` | `400` тот же |
| `POST /api/bookings` | `guestPhone` | `400` тот же |
| `POST /api/masters/clients/notes` | `guestPhone` | `400` тот же |
| `GET /api/admin/users?search=` | строка поиска, **если похожа на телефон** (≥ 5 цифр и нет букв); иначе ищется как есть — иначе сломается поиск по фамилии | — |

### 12.2 Что меняется в ответах

| Поле | Было | Стало |
|---|---|---|
| `AuthResponseDto.phone`, `ProfileDto.phone` | `"+7 999 000-00-00"` — как ввели | `"79990000000"` |
| `MemberDto.phone`, `AdminUserDto.phone` | как ввели | канон |
| `BookingDto.clientPhone` | как ввели | канон |
| `MasterClientDto.phone` / `guestPhone` | как ввели | канон |
| `AdminBookingDto.clientPhone` | как ввели | канон |

**Что делает фронт (T-F1):** одна функция `frontend/src/utils/phone.ts` —
`formatPhone(canonical)`: 11 цифр с `7` → `+7 (999) 000-00-00`; иначе → `+<цифры>`; пустая строка →
пустая строка. Применяется **везде, где номер показывается**. Ввод маской **не ограничивается**
(US-26 п. 6, NFR §9 п. 8) — человек набирает как привык, сервер приводит к канону сам.

### 12.3 Побочные эффекты, которые контракт фиксирует

1. **Аккаунты склеиваются.** Пользователь, зарегистрированный как «8 999…», и он же, вошедший как
   «+7 999…», — один аккаунт. Повторная регистрация в другом формате даёт «номер занят», а не второй
   аккаунт (`AUTH-0xy`).
2. **История гостя склеивается** в `GET /api/masters/clients` без единой строки дополнительного кода:
   группировка идёт по уже каноническим `GuestPhone` (US-26 п. 9).
3. **Миграция удаляет часть аккаунтов** по детерминированному правилу и **останавливается с внятной
   ошибкой**, если схлопывающиеся аккаунты владеют компаниями или оба являются мастерами с записями
   (SPEC §7.1 п. 8, `ARCHITECTURE.md` §14.3). Сервис не в продакшене — потери допустимы, но не молча.
4. **Пароль автосозданного мастера** («Sb» + последние 6 цифр телефона) начинает выводиться из канона.
   Для номеров, введённых с `+7`, результат тот же; для «8 999…» — другой. Отмечается в `CHANGELOG`.

## 20. Чек-лист согласования BE↔FE перед мёржем цикла

1. Тела 400/402/403/404/409 не изменились ни в одном существующем эндпоинте — проверяется диффом
   контроллеров. Единственный **новый** код с телом — `429` (`OnRejected` обязателен).
2. `frontend/src/utils/bookingError.ts`, `companyError.ts`, `memberError.ts`, `planError.ts`
   **не изменены** — проверяется пустым диффом четырёх файлов.
3. Новые мапперы (`uploadError.ts`, `cancelError.ts`, `companyAdminError.ts`) читают `response.data`
   как **строку**, а не объект, и покрыты юнит-тестами.
4. Текст `Unsupported image type — use JPEG, PNG or WEBP` в новом загрузчике **посимвольно совпадает**
   с существующим текстом логотипа (`CompaniesController.cs:281`) — регрессия `CO-0xx` на него опирается.

   через `AuthedImage`/`useAuthedImage` (§5). Проверяется grep'ом по `photos` в JSX.

7. `grep -rn "IFormFile" ServiceBooking.API/` показывает четыре метода, и все четыре зовут
   `ImageUploadService` — второго пути обработки изображений в решении нет (US-25 п. 2).

   все семь точек входа вызывают его, дублей нет (US-26 п. 1). SQL-копия в миграции показана в PR
