# Бриф цикла 28 — «живая витрина» и демо-стенд (услуги)

Заказчик, 2026-09-30: для прохождения проверок Роскомнадзора и платёжного
интегратора сайт должен выглядеть как боевой. Нужно наполнить сервис правдоподобными
данными и держать заготовку под демо-версию на отдельном поддомене.

## Словарь: слово заказчика → что значит в этом цикле
| Слово | Значение |
|---|---|
| «сгенерировать тарифы» | набор публичных тарифов в каталоге (IsActive/IsPublic, см. память tariff-lifecycle-two-flags) с осмысленными лимитами и ценами; **один из них — триал** (механизм триала есть с цикла 18) |
| «разные компании» | несколько организаций (салоны/студии/клиники разных профилей и городов) с владельцами, адресами, логотипами/фото, услугами, ценами, расписанием |
| «разные сотрудники» | мастера у каждой компании с разными услугами, графиками, фото, перерывами и выходными |
| «имитация настоящей работы» | будущие и прошлые записи клиентов: часть слотов свободна, часть занята, есть отменённые/завершённые; витрина, каталог города и страницы записи выглядят живыми |
| «услуги, товары позже» | **только модуль услуг**; товары/заказы (циклы 23–25) НЕ трогать |
| «заготовка под демо» | воспроизводимый (идемпотентный) набор демо-данных + режим демо, который можно развернуть на отдельном поддомене и сбрасывать |
| «на отдельный поддомен» | по бренд-брифу BRIEF_BRAND_AND_DOMAINS.md; имя поддомена — предложить (demo.*), решение за заказчиком |

## Жёсткие требования
- Данные НЕ должны попасть на бой как настоящие клиенты: никаких реальных ПДн, телефоны
  только из зарезервированных диапазонов/заведомо вымышленные, e-mail на example-доменах;
  уведомления (SMS/MAX/e-mail/Push) для демо-записей не отправляются.
- Демо-данные помечаются (флаг), чтобы их можно было отфильтровать, пересоздать и удалить,
  не задев боевые записи. Слоты — относительные к «сегодня» (сдвигаются при пересеве).
- Витрина на бою: вопрос «показывать ли демо-компании в публичном каталоге на проде»
  сформулировать как решение заказчика с рекомендацией и рисками (проверка РКН/интегратора
  видит именно публичное).
- Деление на проходы: A — витринные данные на бою + тарифы, B — демо-режим/поддомен/сброс.
  Аналитик предлагает деление, решение за заказчиком.
- Учесть выкат = deploy-staging, retention live с 30.09, правовой комплект опубликован
  (см. память prod-legal-and-deploy-facts) — не сломать.

## Решение заказчика, 2026-09-30 (после запуска анализа)
Поддомен для демо заведён: **`demo.visit`** — то есть `demo.visit.ezbook.ru` (под-хост
продукта «EZBOOK Запись», `visit.ezbook.ru`). Имя поддомена больше не открытый вопрос;
проход B (демо-режим) разворачивается именно на нём. Точное FQDN и DNS/сертификат
(wildcard или отдельный) — уточнить у заказчика при архитектуре, если есть неясность.
