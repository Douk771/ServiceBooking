# SPEC — цикл 31 ServiceBooking: плашка «Доступна новая версия» в goods (Home Screen)

**Дата: 2026-10-01. Ветка цикла: `cycle/031-goods-update-banner`, отправная точка — `develop` = `e1d7cdb`.**
Истории — `US-31-xx`, задачи — `T-31-xx`, функциональные кейсы — `CY31-`. Цикл только фронтенд goods + конфиг nginx, без API и БД.

## Проблема
goods ставят на экран «Домой» (iOS). Такое приложение приостанавливается, а не перезагружается, и неделями держит старую
сборку. Исправление скролла вкладок кабинета (`fix/goods-cabinet-tabs-scroll`) в браузере заработало сразу, в иконке — только
после того, как пользователь смахнул приложение. Просить об этом конечных пользователей нельзя.

## Истории
- **US-31-01 (P1).** Как пользователь приложения с экрана «Домой», при возврате в него я вижу плашку «Доступна новая
  версия» с кнопкой «Обновить», если на сервере новая сборка. Кнопка перезагружает страницу.
  Критерии: проверка при возврате в приложение (`visibilitychange` → visible) и раз в 5 минут; плашка не перезагружает
  страницу сама (введённые данные не теряются); без новой сборки, при ошибке сети и в dev-режиме плашки нет, ошибок в консоли нет;
  плашка не перекрывает home-indicator iPhone (safe-area).
- **US-31-02 (P1).** Как владелец сервера, я хочу, чтобы `index.html` не залипал в HTTP-кэше телефона: `index.html` и прочее вне
  `/assets/` отдаются с `Cache-Control: no-cache`, хэшированные `/assets/*` — `immutable` на год.

## Не входит
Тихая перезагрузка, изменения sw.js (он остаётся без кэширования и без перехвата запросов), плашка на ezbook.ru.

## Риски
- Конфиг nginx на VPS ставится вручную, после копирования — перезапуск certbot (шапка `deploy/nginx/goods.ezbook.conf`).
- Уже открытые старые приложения получат плашку только после одного ручного перезапуска на новую сборку.
