## §32.20. Сводка: сервер не меняется

| `PUT /api/companies/{id}` | ничего | салон шлёт **две непересекающиеся формы тела**: профиль (§32.22) и правила записи (§32.23). Раньше — одно тело «всё сразу» и отдельное `{cityId, timeZoneId}` |

Новых маршрутов, полей DTO, кодов ответа, миграций и переменных окружения **нет**. `Cycle22RouteTable.golden.txt` не

`ARCHITECTURE_CYCLE32.md` §32.3).

## §32.21. `GET /api/companies/my` — что читает вкладка

Форма — `CompanySettingsDto` (подмножество `CompanyDto`, `additionalProperties: true`). Поля, на которые опирается фронт:

| Поле | Кто читает | Смысл |
|---|---|---|
| `name`, `description`, `phone`, `email`, `logoUrl`, `address`, `yandexMapsUrl`, `twoGisUrl` | профиль | начальные значения формы и шапка |
| `cityId`, `cityName`, `cityRegion` | профиль | значение `CityCombobox` (`label` = «Город, Регион») |
| `timeZoneId`, `utcOffsetMinutes`, `timeZoneIsManual` | профиль | **действующий** пояс (при ручном — ручной) и его смещение |
| `bookingHorizonDays` (1–365, уже нормализовано), `clientRescheduleMinHours` (0–168), `allowSelfBooking`, `requirePrepayment` | правила | начальные значения |
| `planAllowsOnlineBooking`, `planAllowsOnlinePayment` | правила | блокировка флажков тарифом |
| `allowSelfBooking`, `onlineBookingEnabled`, `slug`, `name` | виджет | как раньше |

**Чего в DTO нет (и это осознанно не чинится):** собственного пояса города, когда у салона ручной пояс.
`timeZoneId`/`utcOffsetMinutes` описывают действующий пояс. Как фронт обходится без этого — §32.27.3 и
`ARCHITECTURE_CYCLE32.md` §32.3, §32.6.

## §32.22. `PUT /api/companies/{id}` — тело блока «Профиль компании»

Схема `CompanyProfileUpdateInput`, `additionalProperties: false`. Одна и та же для салона и магазина.

| Ключ | Когда в теле | Значение |
|---|---|---|
| `name` | всегда | обрезанное по краям. Пустое — запрос не уходит (клиентская проверка, текст §32.26) |
| `description` | всегда | обрезанное; `""`, если пусто |
| `phone` | всегда | нетронутое поле — **сохранённое значение как есть**; изменённое — 11 цифр `7XXXXXXXXXX`; пустое — `""` (§32.27.2) |
| `email` | всегда | обрезанное; `""`, если пусто |
| `cityId` | только если город выбран другой | id города |
| `timeZoneId` | **только салон**, только если ручной пояс включили, выключили или изменили (§32.27.3) | IANA-строка — ручной пояс; `null` — сбросить к поясу города |
| `yandexMapsUrl`, `twoGisUrl` | только изменённая ссылка | обрезанная строка; очищенная — `""` (= удалить) |

Никогда не попадают: `address`, `bookingHorizonDays`, `clientRescheduleMinHours`, `allowSelfBooking`,
`requirePrepayment`, `showInPublicListing` (C31 R-4 остаётся в силе).

Ответ 200 — `CompanyDto`. Кабинет его не читает: после успеха (и после сбоя адреса) вызывает `onChanged` —
инвалидация кешей (`ARCHITECTURE_CYCLE32.md` §32.5: салон `['my-companies']` и `['company']`; магазин `['shop', id]`,
`['my-shops']`, `['storefront']`).

## §32.23. `PUT /api/companies/{id}` — тело карточки «Правила записи» (только салон)

Схема `BookingRulesUpdateInput`, `additionalProperties: false`.

| Ключ | Когда в теле | Значение |
|---|---|---|
| `bookingHorizonDays` | всегда | пустое поле или `0` → `0` (сервер ставит 90 по умолчанию); 1–365 — как введено. Вне диапазона — запрос не уходит, текст у поля (§32.26) |
| `clientRescheduleMinHours` | только если поле не пустое | 0–168. Пустое поле = «не трогать», ключа нет |
| `allowSelfBooking` | если тариф разрешает онлайн-запись (`planAllowsOnlineBooking`) | значение флажка |
| `requirePrepayment` | если тариф разрешает онлайн-оплату (`planAllowsOnlinePayment`) | значение флажка |

Заблокированный тарифом флажок в тело **не попадает** — так же, как сейчас (react-hook-form не отдаёт значения
`disabled`-полей). Поля профиля и `showInPublicListing` в теле правил не бывает никогда.

## §32.24. Порядок запросов при одном нажатии «Сохранить» профиля

```
[локально] пустое название → ошибка у поля, запросов нет
[локально] смещение пояса меняется → модалка «Сменить город?» (Отмена → запросов нет)
[локально] адрес изменён → PublicAddressNotice → POST /api/companies/address/notice (Отмена → запросов нет)
PUT /api/companies/{id}            тело §32.22
  └─ 2xx и адрес изменён → PUT /api/companies/{id}/address   { "address": "<как введено>" }
```

- Без изменения адреса — **ровно один** запрос. С адресом — подтверждение уведомления и два PUT, как у магазина с
  цикла 26. Подтверждение — существующий шаг правового контура, не новый запрос.
- Ошибка основного PUT — адрес не отправляется, ничего не сохранено (любой 400 сервер отдаёт до `SaveChanges`).
- Ошибка адреса после успешного PUT — у поля адреса «Не удалось сохранить адрес. Попробуйте ещё раз.», под формой
  «Остальные изменения сохранены», кеши инвалидируются.
- «Сохранить правила» — ровно один `PUT` с телом §32.23, независимо от профиля.

## §32.25. Логотип

`POST /api/companies/{id}/logo`, `multipart/form-data`, поле `file`. Уходит сразу при выборе файла, не ждёт
«Сохранить». Ошибки — `getLogoErrorMessage` (как сейчас в обоих кабинетах). Успех — `onChanged`.

## §32.26. Тексты сервера, по которым фронт выбирает поле (закреплены функциональным тестом CY32-05)

Все — `400 text/plain`, выводятся **дословно** у поля. Сервер проверяет в этом порядке и отвечает первым отказом.

| Текст сервера (дословно) | Поле | Кто может получить |
|---|---|---|
| «Горизонт записи — от 1 до 365 дней» | «На сколько дней вперёд клиент может записаться» | правила (клиент обычно ловит раньше, тем же текстом `HORIZON_OUT_OF_RANGE_MESSAGE`) |
| содержит «Яндекс», либо общий «Ссылка …» (правило цикла 26 §567: общий текст идёт к 2ГИС, если Яндекс не отправляли) | «Яндекс Карты» | профиль |
| содержит «2ГИС» | «2ГИС» | профиль |
| «Окно переноса — от 0 до 168 часов» | «За сколько часов клиент может перенести или отменить запись» | правила |
| «Город не найден» | «Город» | профиль |
| «Неизвестный часовой пояс» | «Часовой пояс (IANA)» | профиль салона |

Остальные ответы — под формой (компонент `InlineError`, `role="alert"`), текстом маппера кабинета:
- салон — `getCompanyManageErrorMessage(err, fallback)` (400 без поля → «Проверьте введённые данные — сервер их не
  принял.», 403 → «Недостаточно прав…», 404 → «Объект не найден…», иначе `fallback`);
- магазин — `getGoodsErrorMessage(err, 'Не удалось сохранить профиль.')`, без изменений; 409 магазина — у поля города.

Клиентские тексты (запрос не уходит): «Введите название салона» / «Введите название магазина» у поля «Название *»;
«Горизонт записи — от 1 до 365 дней» у поля горизонта.

## §32.27. Гарантии сервера, на которые опирается план (✔ по коду `CompaniesController.Update`, строки 291–405)

### §32.27.1 Частичное обновление (SPEC R-3)
- Каждое поле пишется только при `is not null` (строки 300–342). Отсутствующий ключ не трогает колонку.
- EF Core обновляет только изменённые свойства, поэтому два почти одновременных PUT с непересекающимися телами
  (профиль и правила из соседних карточек) не затирают друг друга.
- Любой 400 возвращается до `SaveChangesAsync` — запрос атомарен.
- Доказательство — CY32-01/02: PUT профиля не меняет `bookingHorizonDays`, `clientRescheduleMinHours`,
  `allowSelfBooking`, `requirePrepayment`, `showInPublicListing`, адрес; PUT правил не меняет профиль, город, пояс,
  ссылки, адрес.

### §32.27.2 Телефон (SPEC R-4)
- `company.Phone = dto.Phone` (строка 303) — **без нормализации**. Сервер хранит и отдаёт строку байт в байт.
- `PhoneInput` не вызывает `onChange` при монтировании. Поэтому нетронутое значение уходит тем же, что пришло, и
  первое сохранение профиля без правки телефона номер не меняет (CY32-03 + V32-12).
- После правки поля в БД попадает `7XXXXXXXXXX`. Публичные экраны форматируют его `formatPhone`/`telHref` — вид
  «+7 (900) 000-00-00», ссылка `tel:+7…`. Добавочный номер и иностранный номер после правки записать нельзя —
  принятое решение Q-32-6.

### §32.27.3 Город и часовой пояс салона (`CompanyTimeZoneResolver.ForUpdate`)

| `cityId` в теле | `timeZoneId` в теле | Ручной пояс до запроса | Результат |
|---|---|---|---|
| другой город | нет ключа | нет | пояс нового города, `timeZoneIsManual = false` |
| другой город | нет ключа | да | ручной пояс сохраняется |
| любое | `"X"`, ≠ поясу города | — | `X`, `timeZoneIsManual = true` |
| любое | `"X"`, = поясу города | — | пояс города, `timeZoneIsManual = false` |
| любое | `null` | — | пояс города, `timeZoneIsManual = false` |
| нет ключа | нет ключа | — | без изменений |

- Неизвестный IANA → 400 «Неизвестный часовой пояс» (проверяется даже у салона без города).
- **Салон без города:** `timeZoneId` проверяется, но не применяется (ветка `else if (city is not null)`, строка 389).
  Поэтому флажок ручного пояса недоступен, пока город не выбран.
- Блокировки смены пояса у салона нет (409 бывает только у магазина).

## §32.28. Примеры для prism и тестов

**Салон, правка названия и телефона (город, пояс, адрес, ссылки не трогали):**
```json
{ "name": "Салон Ромашка 2", "description": "Стрижки", "phone": "79001234567", "email": "hello@romashka.ru" }
```

**Салон с ручным поясом, ручной пояс выключен, город тот же, телефон не трогали:**
```json
{ "name": "Салон Ромашка", "description": "", "phone": "8 (3852) 12-34-56 доб. 5", "email": "", "timeZoneId": null }
```

**Правила записи, тариф без онлайн-записи и оплаты, окно переноса очищено:**
```json
{ "bookingHorizonDays": 0 }
```

**Недопустимо (prism mock ответит 422, `tsc` не соберёт литерал с `satisfies`):**
```json
{ "name": "Салон", "description": "", "phone": "", "email": "", "bookingHorizonDays": 30 }
```

## §32.29. Приёмка контракта

- `npx @redocly/cli lint --config ../contracts/redocly.yaml ../contracts/cycle32/openapi.yaml` — чисто.
- `npm run types:api:cycle32` и `npm run contracts:json` в CI не дают diff.
- Тела PUT в `CompanyProfileCard` и `BookingRulesSection` собираются с `satisfies C32['schemas'][…]`. Лишний ключ
  или ключ правил в теле профиля не соберётся (`tsc`).
- Функциональные CY32-01…05 (сервер) и CY32-10…12 (ответы против `contracts/cycle32/openapi.json`) — зелёные.
- Vitest V32- проверяет точный состав тел (`toEqual`, а не `toMatchObject`) там, где форма тела и есть критерий.
- `Cycle22RouteTable.golden.txt` — **без изменений**.
- Найденное расхождение чинится так: неверное тело — во фронте; неполная схема — в `contracts/cycle32/openapi.yaml`,
  затем `types:api:cycle32` и `contracts:json`. Сервер в этом цикле не правится. Если без правки сервера не обойтись,
  это новый вопрос к архитектору, а не молчаливая правка.
