## 111. Общие правила, действующие без изменений

Ничего из перечисленного цикл 9 не меняет — повторено, чтобы разработчикам не приходилось искать:

- `camelCase` в JSON; `enum` — **строками** (`JsonStringEnumConverter`); `DateTime` — ISO-8601 UTC;
  `DateOnly` — `YYYY-MM-DD`; `TimeOnly` — `HH:mm`.
- **Тело осознанных 4xx — голая строка `text/plain`** по-русски (400/402/409/429). 401 и 403 — **пустое
  тело**. `ProblemDetails` не используется, кроме необработанных исключений (500 с `traceId`).
  Единственное исключение — 400 от Identity при регистрации (массив `{code, description}`), цикла 9 не
  касается.
- **451 Unavailable For Legal Reasons** — «требуется принять новую редакцию документов». Все новые
  маршруты цикла 9, кроме анонимных, по умолчанию **закрыты** глобальным `LegalConsentFilter`; в
  allow-list не вносится ни один.
- **402 Payment Required** — «упёрлись в тариф». ⚠️ **Ни один маршрут Web Push 402 не отдаёт** — push
  бесплатен и тарифом не гейтится (SPEC П6).
- **429** — превышен именованный лимит; тело пишет `OnRejected`.
- Пагинация — конверт `PagedResult<T> { items, page, pageSize, total, hasNext }`, `pageSize` по
  умолчанию 20, потолок 100, **клампится, а не 400**; `page` клампится с обеих сторон.
- `Optional<T>` — различение «поле не прислали» и «прислали null». В цикле 9 не требуется ни в одном
  новом теле.
- Base URL фронта — `/api` (`frontend/src/api/client.ts`).

**Всё, что добавляет цикл 9, — аддитивно.** Два ломающих изменения существуют, но они **не в HTTP**, а в
схеме БД и во внутреннем инварианте, и выписаны явным списком «до → после» в `ARCHITECTURE_CYCLE9.md`
§104.3 и §104.5.

## 113. Города и главная (проход A)

### 113.1 `GET /api/cities` — без изменений

Форма ответа, параметры (`search`, `take`), правило «prefix, и только при недоборе — подстрока» и
отсутствие full-text/trigram-индекса остаются как есть. Цикл 9 только **добавляет строки в таблицу**
(миграция `ExpandCityDirectory`, ориентир 310 ± 10 городов вместо 91).

⚠️ Фронтовая правка US-114 **не требует ни одного изменения сервера**: комбобокс перестаёт слать на
сервер полный лейбл `"{Name}, {Region}"` и шлёт `name`. См. `ARCHITECTURE_CYCLE9.md` §103.4.

### 113.2 `GET /api/companies/public` 🆕 — публичный каталог с фильтром по городу

**Анонимный.** Заменяет для главной страницы `GET /api/companies`, который **остаётся и не меняется**.

```
GET /api/companies/public?cityId=42&search=локон&page=1&pageSize=20
→ 200  PagedResult<CompanyDto>
```

| Параметр | Тип | Правило |
|---|---|---|
| `cityId` | `int?` | не передан или пуст → **«Все города»**. Несуществующий, но числовой город → **пустая страница, не 404** (публичный каталог не подтверждает существование справочных записей). **Нечисловое значение → 400** (голая строка, автоматическая проверка модели `[ApiController]`, не `ProblemDetails`) — это ошибка формата запроса, а не значение фильтра |
| `search` | `string?` | подстрока по названию **или** адресу, регистронезависимо, **в SQL**. Комбинируется с `cityId` через «и». Длиннее 200 символов — **не отвергается 400-м, обрезается сервером до 200 символов** перед поиском (тот же приём, что у `pageSize` ниже) |
| `page`, `pageSize` | `int?` | `Pagination.Normalize`, дефолт 20, потолок 100 |

**Элемент — тот же `CompanyDto`, что у `GET /api/companies`,** собранный тем же маппером: `employeeCount`
= 0, `accountSeatsUsed`/`accountSeatsLimit`/`canAddEmployee` = `null` (публичный вызов не считает
использование аккаунта). Второго DTO не заводится.

**Правила видимости не меняются вообще:** в выдачу попадает компания с `isActive` **и**
`showInPublicListing` **и** `allowPublicListing` действующего тарифа. **Город видимости не добавляет и не
отнимает.** Компания без города (`cityId == null`) попадает только во «Все города».

**Порядок** — по `name`, затем по `id` (устойчивый; без него страницы «поедут»).

Ошибки: 400 при нечисловом `cityId` (см. таблицу параметров выше) и 429 (общих лимитов у публичных
списков нет; политика не навешивается — маршрут анонимный и дешёвый). 404 не бывает.

⚠️ **Расхождение с редакцией 1, закрытое в этом документе задним числом**: первая редакция описывала
только 429 и не называла 400 для нечислового `cityId`, а для `search` не оговаривала обрезание длиннее
200 символов — реализация (`CompaniesController.GetPublic`) всегда вела себя так же, как описано выше;
расхождение было только в тексте контракта, не в поведении сервера. Исправлено вместе с
`contracts/cycle9/openapi.yaml` (параметр `cityId`/`search`, ответ `400`).

## 114. Канал MAX и режим доставки (проход B)

### 114.1 `GET /api/notification-channels/offer` — расширено

**Было:** объект с одной ценой, флагом тарифа, текстом риска и его версией — про WhatsApp по умолчанию.

**Стало:** тот же объект **плюс массив `transports[]`** — что вообще предлагается.

```jsonc
{
  "pricePerMonth": null,          // как было: null = опция не предлагается
  "allowedByPlan": false,         // как было
  "riskText": "…",                // ⚠️ теперь из документа ChannelRiskNotice, а не из константы
  "riskVersion": "2026-09-21-draft",
  "transports": [                 // 🆕
    { "transport": "WhatsApp", "displayName": "WhatsApp", "available": true,
      "connectionNotice": null },
    { "transport": "Max",      "displayName": "MAX",      "available": true,
      "connectionNotice": "Для авторизации по QR в MAX нужно отключить пароль входа в мессенджере." }
  ]
}
```

⚠️ **`riskVersion` изменит значение после выката** (`2026-09-18-draft` → версия документа
`ChannelRiskNotice`): цикл сводит два носителя текста к одному (`ARCHITECTURE_CYCLE9.md` §104.8).
Следствие для владельцев: риск надо **принять заново**. Боевых каналов нет.

**`connectionNotice` — текст, который пользователь обязан увидеть ДО привязки**, а не после. Собирает
**сервер**; фронт его печатает и не сочиняет (конвенция §6).

### 114.2 `POST /api/notification-channels` — одно новое необязательное поле

```jsonc
{ "legalEntityForm": "Ip", "inn": "…", "acceptedOwnerTermsVersion": "…",
  "transport": "Max" }          // 🆕 необязательное; отсутствует → "WhatsApp"
```

Аддитивно: старый клиент, не присылающий `transport`, получает WhatsApp-канал ровно как раньше.

| Код | Когда |
|---|---|
| 400 | нераспознанный `transport`; прежние причины (ИНН, форма лица, оферта) без изменений |
| 402 | тариф не разрешает / цена не задана — без изменений |
| 409 | у аккаунта уже есть канал этого **транспорта** в живом состоянии 🆕 (раньше — «уже есть канал») |

### 114.3 Поле `transport` в существующих ответах

Добавляется **аддитивно**, никакие поля не удаляются и не переименовываются:

| Маршрут | Что добавилось |
|---|---|
| `GET /api/notification-channels` | `transport` в каждом элементе |
| `GET /api/notification-channels/{id}` | `transport` |
| `GET /api/admin/notification-channels` | `transport` в элементе + **query-фильтр `?transport=`** |
| `GET /api/admin/notification-channels/summary` | разбивка по транспортам |
| `GET /api/companies/{companyId}/notifications` (журнал доставки) | `transport` в элементе + **query-фильтр `?transport=`** |

**Нераспознанное значение `?transport=` на обоих маршрутах с фильтром → 400**, голая строка по-русски
(автоматическая проверка модели `[ApiController]`, тот же приём, что у `cityId` в §113.2) — не было
названо в редакции 1, дописано здесь и в `contracts/cycle9/openapi.yaml` задним числом; поведение сервера
не менялось.

**Инвариант, который изменился** (`ARCHITECTURE_CYCLE9.md` §104.3): компания может быть назначена
максимум на **один канал каждого транспорта**, а не на один канал вообще.
`POST /api/notification-channels/{id}/companies` при попытке назначить компанию на второй канал **того
же** транспорта отвечает **409**; на канал другого транспорта — 200. Подключение MAX **не трогает и не
отвязывает** существующий WhatsApp-канал.

### 114.4 `GET|PUT /api/companies/{companyId}/notification-settings` — режим доставки

**Ответ пополняется четырьмя полями:**

```jsonc
{
  "enabledTypes": ["BookingConfirmed", "Reminder", "BookingCancelled", "BookingRescheduled"],
  "reminderLeadMinutes": 1440,
  "minLeadMinutes": 120,

  "deliveryMode": "PriorityChannel",      // 🆕 PriorityChannel | AllChannels
  "priorityTransport": "WhatsApp",        // 🆕
  "connectedTransports": ["WhatsApp"],    // 🆕 только для чтения: что реально подключено и живо
  "priorityChannelHealthy": true          // 🆕 только для чтения: приоритетный канал в рабочем состоянии
}
```

**`PUT`** принимает `deliveryMode` и `priorityTransport` дополнительно к прежним полям. Оба
необязательны: не прислали — не меняем.

| Код | Когда |
|---|---|
| 400 | `priorityTransport` не входит в `connectedTransports`; нераспознанные значения; прежние правила про `reminderLeadMinutes`/`minLeadMinutes` без изменений |
| 402 | без изменений: «Недоступно на вашем тарифе» / «Канал не оплачен» ⚠️ **этот маршрут был и остаётся тарифно гейтящимся** — именно поэтому настройка Web Push живёт в другом месте (§115.4) |
| 403 | не владелец компании |

**Что означает режим.**
- `PriorityChannel` (**дефолт, поведение всех существующих компаний не меняется**): одно событие →
  **одна** отправка в `priorityTransport`. Если приоритетный канал не в рабочем состоянии — отправки
  **нет**, в журнале причина `PriorityChannelUnavailable`. **Молчаливого ухода в другой транспорт нет.**
- `AllChannels`: одно событие → **по одной отправке на каждый подключённый и живой транспорт**. В журнале
  это выглядит как одно событие и несколько строк с разными `transport`.
- Один подключённый канал → режим ни на что не влияет; экран обязан это объяснить, а не показывать
  бессмысленный выбор.

**Режим применяется в момент постановки в очередь.** Уже поставленные сообщения адресата не меняют.
Экран обязан сказать это владельцу.

**Отписка сильнее режима:** номер в `NotificationOptOut` не получает ничего **ни в одном** транспорте, и
ссылка отписки из сообщения MAX гасит WhatsApp, и наоборот.

**Владелец предупреждается текстом при включении `AllChannels`:** клиент получит два одинаковых
сообщения на один номер.

### 114.5 `POST /api/notifications/provider-webhook/{transport}/{token}` 🆕

Анонимный, политика лимита `notifications-webhook` (600/мин на IP).

- `{transport}` — `whatsapp` | `max` (регистронезависимо). **Нераспознанный → 404**, а не 400: маршрут не
  рассказывает, какие транспорты существуют.
- `{token}` — тот же платформенный `Notifications:WebhookToken`. **Неверный/отсутствующий → 401**, тело
  пустое (`EmptyResult`, не `ProblemDetails`) — обработчик токена общий с существующим
  `POST /api/notifications/provider-webhook/{token}`, тот же код и то же обоснование, что у него
  (API_CONTRACT_CYCLE4.md §19.2/33).
  ⚠️ **Расхождение редакции 1, закрытое в этом документе задним числом**: `contracts/cycle9/openapi.yaml`
  до правки объединял «нераспознанный транспорт либо неверный токен» под одним 404 — реализация
  (`NotificationsController.HandleWebhookAsync`) всегда отвечала 401 на неверный токен, унаследовав это от
  цикла 4; расхождение было только в тексте схемы, не в поведении сервера. Исправлено вместе с
  `contracts/cycle9/openapi.yaml` (добавлен ответ `401`, `404` сужен до «нераспознанный транспорт»).
- **Существующий `POST /api/notifications/provider-webhook/{token}` остаётся и означает WhatsApp** — он
  мог быть уже прописан в настройках экземпляра у провайдера.
- Нераспознанный формат тела **не роняет обработчик**: 200 + одна строка лога Information.
- ⚠️ Для devops: новый маршрут **обязан получить маскирование токена в access-логе nginx**, как
  существующий.

### 114.6 Отписка — без изменений

`GET|POST /api/notifications/unsubscribe/{token}`, публичная страница `/u/:token`. Ссылка из сообщения
**любого** транспорта ведёт сюда же и гасит все транспорты. Маршрут остаётся в
`CONSENT_GATE_BYPASS_PATHS` фронта.

## 115. Web Push мастеру (проход C)

Все маршруты — под `[Authorize]`, **тарифом не гейтятся**, 402 не возвращают никогда.

### 115.1 `GET /api/push/config` 🆕

Одним запросом отдаёт всё, что нужно фронту, чтобы решить, показывать ли тумблер и что объяснить.

```jsonc
{
  "enabled": true,                         // false = подсистема выключена на платформе
  "publicKey": "BHk…",                     // VAPID public key, base64url; null когда enabled=false
  "maxSubscriptionsPerUser": 10,
  "companies": [                           // компании, где я персонал
    { "companyId": "…", "companyName": "Локон", "staffPushEnabled": true }
  ]
}
```

- **`publicKey` — единственный способ, которым ключ попадает в браузер.** Второй `VITE_*`-переменной не
  заводится, и приватный ключ в бандл попасть физически не может.
- `enabled: false` означает `Notifications:StaffPush:Provider = logging` — **штатное выключенное
  состояние**, а не сбой. Фронт объясняет это текстом и не предлагает подписку.
- `companies[].staffPushEnabled: false` → **разрешение у мастера не запрашивается вовсе** (SPEC US-118).

### 115.2 `GET /api/push/subscriptions?currentEndpoint=…` 🆕

Список **моих** устройств. Чужие не видны ни при каких параметрах — выборка всегда по `userId` из токена.

```jsonc
{ "items": [
  { "id": "…", "deviceLabel": "Chrome на Windows", "createdAtUtc": "…",
    "lastSuccessAtUtc": "…", "isCurrent": true }
] }
```

⚠️ **`p256dh` и `auth` не отдаются ни в одном DTO** — ни мастеру, ни владельцу, ни суперадмину.
`isCurrent` считает сервер, сравнивая с `currentEndpoint`; без параметра — всегда `false`.

### 115.3 `POST /api/push/subscriptions` 🆕 — подписать это устройство

```jsonc
{ "endpoint": "https://fcm.googleapis.com/fcm/send/…",
  "keys": { "p256dh": "BN…", "auth": "k9…" },
  "deviceLabel": "Chrome на Windows" }        // необязательно, ≤100
```

**Владелец подписки берётся из токена, а не из тела** — поля владельца в контракте нет вовсе, поэтому
«создать чужую подписку» невозможно по форме запроса.

| Исход | Код | Поведение |
|---|---|---|
| новый endpoint | **201** | создана |
| **тот же endpoint, тот же пользователь** | **200** | обновлены ключи и метка; **строка не дублируется** (уникальный индекс по endpoint) |
| **тот же endpoint, другой пользователь** | **200** | ⚠️ **подписка переназначается вызывающему**, ключи перезаписываются. Это намеренно: общий компьютер в салоне — реальный сценарий, и «уведомления с именами клиентов приходят тому, кто зашёл до меня» недопустимо. 409 здесь был бы хуже |
| превышен потолок (10) | **201** | создана; **самая старая по `createdAtUtc` удаляется** молча — это не ошибка пользователя |
| `endpoint` пуст / > 500 символов / не URL; `keys` пусты | **400** | текст по-русски |
| подсистема выключена (`enabled: false`) | **409** | «Уведомления на устройство сейчас недоступны» |

Политика лимита — новая именованная **`push-subscribe` (20/час на пользователя)**.

### 115.4 `DELETE /api/push/subscriptions/{id}` и `DELETE /api/push/subscriptions/current` 🆕

| Маршрут | Назначение |
|---|---|
| `DELETE /api/push/subscriptions/{id}` | отключить **любое** моё устройство, в том числе не то, с которого зашёл («забыл выйти на компьютере в салоне»). → **204** |
| `DELETE /api/push/subscriptions/current` с телом `{ "endpoint": "…" }` | вызывается фронтом **при выходе из аккаунта**, идемпотентен. → **204** даже если строки уже нет |

⚠️ Чужая подписка даёт **404, а не 403** — существование чужой строки не подтверждается.
Фронт при отключении **обязан** вызвать и `pushManager.getSubscription()?.unsubscribe()` в браузере:
«просто спрятали кнопку» приёмку не проходит.

**Удаление аккаунта** (`POST /api/profile/delete-account`) удаляет подписки этого пользователя **в той же
транзакции**. Контракт этого маршрута не меняется.

### 115.5 `GET|PUT /api/companies/{companyId}/staff-push-settings` 🆕 — настройка компании

```jsonc
{ "staffPushEnabled": true }
```

- **По умолчанию `true`** — включая компании, созданные до цикла, и компании без строки настроек.
- Доступ: владелец компании и суперадмин. **Мастеру — 403** (явный `Forbid`, не пустое значение).
- **Тарифом не гейтится и канала у провайдера не требует.** 402 этот маршрут не возвращает никогда.
- Выключение **гасит доставку, но не удаляет подписки мастеров**. Включили обратно — уведомления
  возобновились **без перелогина и без повторной подписки**.
- `[RequiresOwnerTerms]` — действует, как у прочих владельческих действий.

⚠️ **Почему отдельный маршрут, а не поле в `notification-settings`:** тот маршрут отдаёт 402 при
`AllowNotificationChannel = false`, то есть **сегодня недоступен ни одному владельцу**; бесплатная
функция не может жить за платным гейтом. Обоснование целиком — `ARCHITECTURE_CYCLE9.md` §105.4.

### 115.6 Что уходит в push (это не HTTP, но это контракт между сервером и service worker)

Тело push-сообщения, зашифрованное по RFC 8291, — JSON:

```jsonc
{ "title": "Новая запись",
  "body": "Стрижка · 24.09 в 14:00 · Анна Петрова",
  "tag": "b-<bookingId>",
  "url": "/my-bookings?booking=<bookingId>" }
```

⚠️ **Телефона клиента здесь нет** (SPEC П8) и быть не должно: уведомление рисует операционная система, в
том числе на личном телефоне мастера и на заблокированном экране.
`tag` схлопывает повторы по одному визиту. `url` — **относительный путь**, service worker сам добавляет
origin; абсолютный URL в теле открыл бы дорогу к открытию произвольного адреса.

⚠️ **Исправление (post-cycle9 review):** изначально здесь был записан `/cabinet?tab=bookings&booking=…`
— несуществующая вкладка кабинета (набор вкладок — `dashboard | companies | schedule | clients | reports
| mailing | notifications`, и `CabinetPage` query-строку вообще не читает). Реальный экран записей
мастера — маршрут `/my-bookings` (`frontend/src/App.tsx`, роли `Master`/`CompanyOwner`/`SuperAdmin`).

**Заголовки запроса к push-сервису:** `TTL = min(3600, секунд до начала визита)`, `Urgency: high`,
`Topic: b-<bookingId>`.

## 116. Коды ошибок: сводная таблица цикла

| Код | Где встречается в цикле 9 | Тело |
|---|---|---|
| **200/201/204** | штатные ответы | JSON / пусто |
| **400** | нераспознанный `transport`; `priorityTransport` не подключён; невалидный `endpoint`/`keys`; правила заявки на канал | **голая строка по-русски** |
| **402** | только `PUT /notification-settings` (как было). ⚠️ **Никогда — на маршрутах push** | строка |
| **403** | не владелец компании (`staff-push-settings`), не персонал | **пусто** |
| **404** | чужая подписка; нераспознанный транспорт в пути вебхука; несуществующая компания | пусто |
| **409** | второй канал того же транспорта у аккаунта; назначение компании на второй канал того же транспорта; подписка при выключенной подсистеме | строка |
| **429** | `push-subscribe` (20/час), `notifications-webhook` (600/мин) | строка от `OnRejected` |
| **451** | все новые неанонимные маршруты, если не принята новая редакция документов | как было |

## 117. Что в контракте НЕ появляется

Перечислено, чтобы никто не искал и не «дописал заодно»:

- **Нет** эндпоинта отправки push вручную/тестового push. Отправку инициирует только событие «создана
  запись».
- **Нет** эндпоинта «прочитать чужие подписки» — ни владельцу, ни суперадмину. Список устройств видит
  только их владелец.
- **Нет** эндпоинтов push для других событий (отмена, перенос, напоминание) — SPEC П7.
- **Нет** персональной настройки мастера «не уведомлять меня» сверх подписки устройства — Q5.
- **Нет** CRUD городов — Р3.
- **Нет** фолбэка между транспортами и тумблера автоподмены — §3 SPEC, Q7в.
- **Нет** изменений в `GET /api/companies`, `GET /api/cities`, `POST /api/bookings`, во всех маршрутах
  биллинга и правового контура.
- `POST /api/notification-channels/{id}/test-message` — **без изменений**, тот же кулдаун для обоих
  транспортов.

## 118. Чек-лист фронтенд-разработчика

1. `npm run types:api9` → `src/types/api-cycle9.generated.ts`. Перечисления `NotificationTransport`,
   `NotificationDeliveryMode` и новые `NotificationReason` — **оттуда**, не строковыми литералами.
2. Мок: `npx @stoplight/prism mock contracts/cycle9/openapi.yaml --port 4010`, затем
   `VITE_API_TARGET=http://localhost:4010 npm run dev`. Бэкенд ждать не нужно.
3. Новый домен ошибок = **новый маппер** `src/utils/*Error.ts` (`pushError.ts`), а не `catch` с текстом в
   компоненте. Маппер обязан пережить тело, которое не строка.
4. Данные — только через `src/api/<домен>.ts` + react-query. Новые модули: `api/push.ts`,
   расширение `api/companies.ts` (`getPublic`), `api/notifications.ts` (режим доставки).
5. Русские тексты состояний и причин **берутся из ответа сервера**, не собираются из кусочков.
6. Выбор города на главной хранится в `localStorage` под ключом `home-city` — **не в `authStore`**.
7. Фильтрации массивов в памяти на главной не остаётся ни одной строки.

## 119. Чек-лист бэкенд-разработчика

1. **Контракт первичен**: новое поле или код ответа — сначала в `contracts/cycle9/openapi.yaml`, потом в
   код.
2. DTO — только `record` с позиционными параметрами; маппинг руками; мелкие DTO — в конце файла
   контроллера.
3. Права: `[Authorize]` + приватный предикат, «членская» половина **обязана** идти через
   `Services/CompanyMembership.cs`. Своих `AnyAsync` по `CompanyMembers` не заводить.
4. «Посчитал → записал» — транзакция + `AdvisoryLock`. Новый ключ цикла: `push-subscriptions:{userId}`.
5. Пагинация — только `PagedResult` + `Pagination.Normalize`.
6. Секреты — только `SecretProtector`. Ключи подписки шифруются строковой перегрузкой, AAD
   `push-subscription:{id}`.
7. Время, задержка, случайность — через `INotificationClock`/`IDispatchDelay`/`IPauseGenerator`.
   `DateTime.UtcNow` и `Task.Delay` в такой логике — регресс.
8. Фоновая работа — только `IScheduledTask` + одна строка регистрации.
9. Правило уничтожения — один файл в `Services/Retention/Rules/` + **поимённая** регистрация.
10. Нераспознанное значение конфигурации **роняет старт**; отсутствующее трактуется в более строгую
    сторону.
11. Enum'ы, участвующие в SQL-фильтрах индексов и битовых масках, — **append-only**.
12. Новый маршрут по умолчанию закрыт гейтом 451 — это намеренное направление ошибки.
13. Новую именованную политику лимита надо **навесить атрибутом**: «не навесил» = «лимита нет».

## 120. Как QA проверяет сходимость машинно

```bash
# 1. Форма интерфейса: реальный бэкенд против схемы
schemathesis run contracts/cycle9/openapi.yaml --base-url http://localhost:5000 --checks all

# 2. Фронтовые типы не разъехались со схемой

npx @redocly/cli lint contracts/cycle9/openapi.yaml
```

Расхождение любого из трёх — красный результат приёмки, независимо от того, что написано в отчётах
разработчиков.
