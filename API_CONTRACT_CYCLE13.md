# API CONTRACT — цикл 13 (адрес компании: карты и мягкая верификация)

**Разделы §230–§241.** Решения — `ARCHITECTURE_CYCLE13.md` §200–§219. **Машиночитаемая форма —
`contracts/cycle13/openapi.yaml`; при расхождении текста и схемы прав YAML.**

**Главное в одной фразе: серверная часть есть только у третьей задачи цикла.** Карусель галереи и
порядок наложения логотипа — чистый фронтенд: данные уже приходят в `company.photos`
(`API_CONTRACT_CYCLE10.md` §129), новых запросов, эндпоинтов и полей они не требуют (§241). Ссылки в
Яндекс.Карты и 2ГИС строятся в браузере из `address` + `cityName`, которые уже есть в `CompanyDto`, —
публичная страница компании **не получает ни одного нового запроса**.

**Ломающих изменений в цикле нет.** Всё новое — добавочное; ни одно поле не удалено и не переименовано.

## §230. Конвенции (действуют без изменений, повторены, чтобы не искать)

- `camelCase` в JSON; перечисления — строками; `DateTime` — ISO-8601 UTC.
- Тела ошибок **400/402/409/410/429** — **голая строка** (`text/plain`), **401/403** — **пустое** тело,
  **404** — пустое тело там, где существование объекта не подтверждается. `ProblemDetails` не
  используется (кроме автовалидации `[ApiController]`).
- Новые поля в ответах — **добавочные**. Фронт обязан корректно работать при их отсутствии (сервер
  старой версии = «проверка недоступна, адрес не подтверждён»), тем же приёмом, каким `photos: null`
  читается как пустая галерея.
- `null` у вычисляемого поля означает «сервер этого не считал для данного вызывающего», а не «нет
  значения» (конвенция `historyEventCount`/`photos` цикла 10).

## §232. `CompanyDto` — два добавочных поля

| Поле | Тип | Где заполняется | Смысл |
|---|---|---|---|
| `addressVerification` | `CompanyAddressVerificationDto \| null` | только там, где вызывающий **управляет** компанией | состояние проверки адреса. `null` = «не вычислялось для этого вызывающего» (аноним, клиент) |
| `addressPoint` | `{ latitude, longitude } \| null` | только `GET /api/companies/{slug}` | точка для метки на карте. `null`, если координат нет или их нельзя хранить |

`CompanyAddressVerificationDto`:

| Поле | Тип | Смысл |
|---|---|---|
| `available` | `boolean` | проверка адреса доступна: рубильник включён **и** вызывающий управляет компанией. `false` → интерфейс **не рисует** кнопку «Проверить адрес» вовсе |
| `status` | `"Verified" \| "Unverified"` | вычисляется сервером: `Verified`, только если текущий текст адреса совпадает с тем, который подтверждали |
| `verifiedAt` | `string \| null` (date-time) | когда подтвердили; `null` при `Unverified` |
| `precision` | `"House" \| "Street" \| "Locality" \| "Other" \| null` | с какой точностью карта нашла адрес; `null` при `Unverified` |

**Клиенту статус не показывается** (решение продукта): на анонимной публичной странице
`addressVerification` равно `null`, поэтому показать его невозможно даже по ошибке. `addressPoint` при
этом публичен — точная метка это польза клиенту, а не ярлык «непроверенный салон».

**Где `addressPoint` не `null`:** одновременно должны выполняться три условия — включён рубильник
хранения результатов (`AddressVerification:StoreResults`), адрес подтверждён, точность `House`. В
штатном состоянии прода после этого цикла поле **всегда `null`**, и это нормально: ссылки на карты
тогда ведут на поиск по тексту (§239).

## §233. `POST /api/companies/address/lookup` — НОВЫЙ

Поиск вариантов адреса по картографическому справочнику. **Ничего не сохраняет.** Один эндпоинт
обслуживает и создание компании (её ещё нет), и настройки существующей.

Доступ: `[Authorize]`. Если передан `companyId` — вызывающий обязан управлять этой компанией
(владелец или `SuperAdmin`), иначе **404 с пустым телом** (существование чужой компании не
подтверждается). Лимит запросов — политика **`address-verify`** (30/час на пользователя).

Запрос:

```json
{ "address": "Ленина 5", "cityId": 22, "companyId": "3f7c…" }
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `address` | `string` | да | 1…300 символов после обрезки пробелов. Пусто → **400** «Укажите адрес» |
| `cityId` | `int \| null` | нет | подсказка города. Несуществующий или неактивный → **400** «Город не найден». Не передан и передан `companyId` → берётся город компании. Нет ни того, ни другого → поиск без города, предупреждение `CityMismatch` в этом случае не выдаётся |
| `companyId` | `uuid \| null` | нет | для какой компании проверяем (нужно для города и для прав) |

Ответ **200** `AddressLookupResultDto`:

```json
{
  "outcome": "Ok",
  "queriedAddress": "Барнаул, Ленина 5",
  "candidates": [
    {
      "formattedAddress": "Россия, Алтайский край, Барнаул, проспект Ленина, 5",
      "precision": "House",
      "cityName": "Барнаул",
      "point": null,
      "warnings": []
    }
  ],
  "warnings": [],
  "attribution": "© Яндекс"
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `outcome` | `"Ok" \| "Empty" \| "Unavailable"` | что произошло. `Ok` — варианты есть; `Empty` — карта ответила, но ничего не нашла; `Unavailable` — таймаут/ошибка/нечитаемый ответ внешнего сервиса |
| `queriedAddress` | `string` | что именно сервер отправил в карту («город, адрес») — чтобы владелец видел, по чему искали |
| `candidates` | массив, **0…5** | найденные варианты в порядке убывания релевантности, как их вернула карта |
| `candidates[].formattedAddress` | `string` | полное написание, в котором адрес знает карта. Именно эту строку интерфейс подставляет в поле и отправляет в §234 |
| `candidates[].precision` | `"House" \| "Street" \| "Locality" \| "Other"` | точность найденного |
| `candidates[].cityName` | `string \| null` | населённый пункт из ответа карты |
| `candidates[].point` | `{ latitude, longitude } \| null` | координаты. **`null`, если хранить результаты геокодирования не разрешено** (`StoreResults: false`) — это штатное состояние |
| `candidates[].warnings` | массив предупреждений | что не так именно с этим вариантом (точность, другой город) |
| `warnings` | массив предупреждений | что не так с запросом в целом (`NotFound`, `Unavailable`) |
| `attribution` | `string` | обязательная по лицензии подпись; показывается **как прислал сервер**, своей формулировки интерфейс не придумывает |

Коды ответов:

| Код | Когда | Тело |
|---|---|---|
| 200 | всегда, когда запрос корректен и вызывающему это положено — **включая** «не нашли» и «карта недоступна» | `AddressLookupResultDto` |
| 400 | пустой/слишком длинный адрес, неизвестный город | голая строка |
| 401 | нет токена | пусто |
| **404** | **рубильник проверки выключен** (`AddressVerification:Provider = logging`) — функции нет; либо `companyId` чужой/не существует | пусто |
| 429 | лимит `address-verify` | голая строка |

⚠️ **404 при выключенном рубильнике — намеренно.** «Выключено» значит «функции нет», а не «есть и
ничего не делает». Интерфейс не должен доводить до этого ответа вовсе: признак —
`company.addressVerification.available`.

## §234. `PUT /api/companies/{id}/address` — НОВЫЙ

Сохранить адрес компании и, если попросили, подтвердить его по карте. **Единственный эндпоинт,
который пишет поля проверки.** Работает **всегда**, в том числе при выключенном рубильнике: сохранение
адреса не должно зависеть от внешнего сервиса.

Доступ: `[Authorize]` + право управлять компанией (владелец или `SuperAdmin`), иначе 403/404 по
существующему правилу `CanManageCompany`. Лимит — та же политика **`address-verify`**.

Запрос:

```json
{ "address": "Россия, Алтайский край, Барнаул, проспект Ленина, 5", "verify": true }
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `address` | `string` | да | 0…300 символов. **Пустая строка = стереть адрес** (`Address` становится `null`, проверка очищается). Это отличается от `PUT /api/companies/{id}`, где `null` значит «не трогать» |
| `verify` | `boolean` | нет, по умолчанию `false` | `true` = «сервер, найди эту строку в карте и подтверди её сам» |

Поведение:

| Ситуация | Что записано | `outcome` | Код |
|---|---|---|---|
| `verify: false` | адрес как прислали, проверка очищена → `Unverified`. **Внешних вызовов нет** | `Ok` | 200 |
| `verify: true`, карта нашла вариант, совпадающий с присланной строкой | адрес, `verifiedAt`, `precision`; координаты — **только если их разрешено хранить** | `Ok` | 200 |
| `verify: true`, варианты есть, но ни один не совпал с присланной строкой | адрес как прислали, `Unverified` | `Ok` + предупреждения | 200 |
| `verify: true`, карта ничего не нашла | адрес как прислали, `Unverified` | `Empty` | 200 |
| `verify: true`, карта недоступна/таймаут (≤5 с) | адрес как прислали, `Unverified` | `Unavailable` | 200 |
| `verify: true`, рубильник выключен | адрес как прислали, `Unverified`. Внешних вызовов нет | `Disabled` | 200 |

**Подтверждение ставит только сервер, по результату своего собственного обращения к карте.** Поля
вида «считай этот адрес подтверждённым» в контракте нет и не будет: иначе через прямой вызов API в
базу попал бы «подтверждённый» адрес, которого никто не проверял.

Ответ **200** `CompanyAddressUpdateResultDto`:

```json
{
  "company": { "...": "полный CompanyDto, как у PUT /api/companies/{id}" },
  "verification": {
    "outcome": "Ok",
    "status": "Verified",
    "verifiedAt": "2026-09-24T10:15:00Z",
    "precision": "House",
    "warnings": [],
    "attribution": "© Яндекс"
  }
}
```

Полный `CompanyDto` возвращается затем, чтобы кеш интерфейса обновлялся одним ответом, как это уже
делает `PUT /api/companies/{id}`.

Коды: **200** (все исходы выше), **400** (адрес длиннее 300), **401**, **403** (не управляет
компанией), **404** (компании нет), **415** (тело не `application/json`), **429**.

**Никогда не возвращает 502/504.** Недоступность карты — это `outcome: "Unavailable"` в теле 200:
неудача внешнего сервиса не является неудачей операции «сохранить адрес владельца», и она не имеет
права мешать править свою компанию.

## §235. `PUT /api/companies/{id}` — не меняется, но у `address` появилось следствие

Форма запроса и ответа та же. `address` по-прежнему: `null`/отсутствует — не трогать, строка —
записать.

**Новое следствие:** статус подтверждения вычисляется сервером из сравнения текущего текста адреса с
тем, который подтверждали. Поэтому любая правка адреса через этот эндпоинт (кабинет владельца,
суперадмин, прямой вызов API, скрипт) **автоматически** делает адрес `Unverified`. Геокодер при этом
**не вызывается** — ни одного внешнего запроса на сохранении настроек компании.

То же касается `POST /api/companies`: адрес новой компании всегда `Unverified`, новых полей у создания
компании не появилось. Если владелец пользовался проверкой при создании, интерфейс делает **один**
дополнительный `PUT /api/companies/{id}/address` сразу после успешного создания.

## §236. Предупреждения: коды и кто пишет текст

`warnings[]` — массив объектов `{ code, message }`. **Текст собирает сервер**; интерфейс показывает
`message` и строит логику по `code` (вторая версия формулировок на фронте разошлась бы с серверной —
конвенция проекта).

| `code` | Когда | О чём обязан сказать текст |
|---|---|---|
| `NotFound` | карта не нашла ничего | что адреса может не быть в карте и его можно сохранить как есть. **Без тона «вы ошиблись»** |
| `PrecisionStreet` | найдена только улица | что клиент не найдёт конкретный дом |
| `PrecisionLocality` | найден только населённый пункт/район | то же, ещё грубее |
| `PrecisionOther` | карта не смогла определить уровень | что проверку нельзя считать состоявшейся |
| `CityMismatch` | населённый пункт найденного адреса ≠ город компании | что от города зависят **часовой пояс** и **город в каталоге**, и что стоит проверить поле «Город» |
| `Unavailable` | внешний сервис недоступен | «Не удалось проверить адрес, попробуйте позже», и что сохранение при этом не заблокировано |

**Город компании автоматически не меняется никогда** — только предупреждение: молчаливая подмена
города сдвинула бы время напоминаний.

Интерфейс обязан связать предупреждение с полем адреса программно (`aria-describedby`), а не только
цветом текста; предупреждение — текст рядом с полем, не модальное окно и не `alert`.

## §237. Что интерфейс обязан читать из ответа (и чего не имеет права выводить сам)

| Вопрос интерфейса | Единственный правильный источник |
|---|---|
| Показывать ли кнопку «Проверить адрес»? | `company.addressVerification?.available === true` |
| Подтверждён ли адрес? | `company.addressVerification?.status` (поля нет → считать `Unverified`) |
| Когда подтвердили? | `company.addressVerification?.verifiedAt` |
| Вести ссылку на точку или на поиск? | `company.addressPoint` (нет → поиск по тексту) |
| Что показать владельцу после проверки? | `verification.outcome` + `verification.warnings[].message` |
| Какая подпись правообладателя? | `attribution` из ответа |
| Есть ли у салона фото и какое обложка? | без изменений: `company.photos`, `isCover`/`position === 0` |

Ничего из этого нельзя выводить из роли в JWT, из состава `authStore` или из того, что интерфейс сам
отправил в запросе.

## §238. Лимиты запросов

Новая, **десятая** именованная политика: **`address-verify`** — 30 запросов в час, ключ разбиения —
идентификатор пользователя (оба эндпоинта требуют авторизации, анонимного случая нет). Висит на
`POST /api/companies/address/lookup` **и** на `PUT /api/companies/{id}/address`: оба могут дойти до
платного геокодера. Тело 429 — голая строка, как у остальных политик.

Геокодер вызывается **только** по явному действию владельца или суперадмина. Ни один просмотр
публичной страницы, ни один заход в каталог, ни одно сохранение настроек компании геокодер не дёргают.

## §239. Ссылки в карты — контракт фронтенда (сервер в них не участвует)

Серверных полей и эндпоинтов у этой задачи нет. Ссылки собирает единственный модуль
`frontend/src/utils/mapLinks.ts` из уже приходящих `company.address`, `company.cityName` и
необязательного `company.addressPoint`:

| Состояние | Яндекс Карты | 2ГИС |
|---|---|---|
| точка известна (`addressPoint`) | метка на точке, масштаб уровня дома | поиск по тексту + центр карты на точке |
| точки нет (штатно) | поиск по тексту «город, адрес» | поиск по тексту «город, адрес» |

Обязательное: порядок в запросе — **«город, адрес»** (без города «ул. Ленина, 5» открывает другой
регион); координаты в адресах обоих сервисов идут **`долгота,широта`**; всё кодируется
`encodeURIComponent`; у ссылок `target="_blank" rel="noopener noreferrer"`, доступные имена «Открыть
адрес в Яндекс Картах» / «Открыть адрес в 2ГИС», зона нажатия ≥44 px. Адрес пуст → ни адреса, ни
ссылок, пустых кнопок не появляется. Ссылки работают и для неподтверждённого адреса, и для
неавторизованного посетителя.

## §240. Автосверка контракта (для QA)

```bash
# Форма реализации против контракта — инструментом, без ручного написания тестов
schemathesis run contracts/cycle13/openapi.yaml --base-url http://localhost:5000 --checks all

# Мок для фронта, пока бэкенда нет
npx @stoplight/prism mock contracts/cycle13/openapi.yaml --port 4013

# Типы фронта против контракта: перегенерировать, diff обязан быть пустым
cd frontend && npm run types:api:cycle13
git diff --exit-code frontend/src/types/api-cycle13.generated.ts
```

⚠️ Прогон выполняется **только при выключенном рубильнике** (`AddressVerification:Provider = logging`),
иначе инструмент начнёт слать запросы в платный геокодер.

Автосверка проверяет форму, но не смысл. Дополнительно обязательны: матрица прав (аноним / клиент /
мастер / владелец / `SuperAdmin`) на оба новых эндпоинта; матрица рубильника (выключен: `lookup` →
404, `available: false`, `PUT …/address` работает); проверка, что `addressVerification` отсутствует в
анонимном ответе; проверка, что сохранение адреса не блокируется при недоступном геокодере.

## §241. Чего цикл 13 в API НЕ меняет (важно не «починить заодно»)

- **Все четыре эндпоинта фотографий** (`GET/POST /api/companies/{id}/photos`,
  `DELETE …/photos/{photoId}`, `PUT …/photos/order`) — ни параметров, ни форм ответа, ни лимита 10, ни
  дедупа, ни уплотнения позиций. Карусель — **чистый фронтенд**: `company.photos` уже приходит вместе
  с компанией (`API_CONTRACT_CYCLE10.md` §129), и публичная страница не получает ни одного нового
  запроса.
- **`coverPhotoUrl` / `coverThumbnailUrl` / `photos`** — правила заполнения по эндпоинтам прежние
  (§129 цикла 10): `photos` только у `GET /api/companies/{slug}`, `null` = «этот эндпоинт список не
  отдаёт», `[]` = «фотографий нет».
- **`POST /api/companies`** — ни одного нового поля; адрес новой компании всегда `Unverified`.
- **`GET /api/companies/public`** — параметры `cityId`/`search`/`page`/`pageSize` и правила поиска
  (подстрока по названию **или** адресу, в SQL) не меняются.
- **Город и часовой пояс** (`cityId`, `timeZoneId`, `timeZoneIsManual`) — ни формы, ни правил; город по
  адресу автоматически не меняется.
- **Каталог опций, тарифы, суперадминка цен** — новой платной опции цикл не создаёт; ссылки и проверка
  доступны на всех тарифах.
- **Виджет `/embed/:slug`** — ни карусели, ни ссылок на карты; поведение записи не меняется.
- **Уведомления** — шаблоны, каналы и доставка не затронуты; ссылок на карты в сообщениях нет.
