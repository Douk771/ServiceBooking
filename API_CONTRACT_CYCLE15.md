## §280. Конвенции, действующие без изменений

- `camelCase` в JSON, enum — строками, `DateTime` — ISO-8601 UTC, `DateOnly` — `YYYY-MM-DD`,
  `TimeOnly` — `HH:mm:ss`.
- Тела ошибок **400/402/409/410/429/503 — голая строка** (`text/plain; charset=utf-8`),
  **401/403 — пустое тело**, **404 — пустое тело** там, где существование объекта не подтверждается.
- `ProblemDetails` не используется (кроме автовалидации `[ApiController]`).
- Все новые поля **добавочные**; цикл не удаляет и не переименовывает ни одного существующего поля.
- `null` у вычисляемого поля = «сервер не считал это для данного вызывающего», а **не** «нет
  значения» (конвенция цикла 13 п. 7).
- Отсутствие нового поля в ответе (сервер старой версии) фронт обязан читать как «функции нет»:
  ссылок в карты нет, кнопки «Перенести» нет.

## §282. `CompanyDto` — три добавочных поля

Поля приписаны **в конец** записи (конвенция §115), приходят во всех ответах, где `CompanyDto`
уже возвращается.

```jsonc
{
  // ... всё, что было раньше, без изменений ...

  // Ссылка, которую владелец вставил сам. null = поле не заполнено → интерфейс НЕ показывает
  // переход в этот сервис вообще (0-bis П1). Строка сохранена байт в байт, включая query.
  "yandexMapsUrl": "https://yandex.ru/maps/org/syrovarnya/11766054863/?ll=83.795110%2C53.330510&z=17",
  "twoGisUrl": null,

  // За сколько часов до начала визита клиент ещё может перенести запись сам. Всегда число
  // (дефолт 2). 0 = «до самого начала визита». Настройка компании, а не константа продукта.
  "clientRescheduleMinHours": 2
}
```

Видимость: **все три поля отдаются любому вызывающему, включая анонимного** — это публичные
сведения салона (ссылки показываются на публичной странице; окно переноса нужно интерфейсу, чтобы
объяснить клиенту правило до того, как сервер его применит). Прав по ним не считается, `null`
у ссылки означает именно «не заполнено», а не «не вычислено».

⚠️ **Ссылки НЕ строятся сервером и не достраиваются.** Поля цикла 13 `address`, `cityName`,
`addressPoint` для карт больше не используются нигде; `addressPoint` остаётся как был и к этому
циклу отношения не имеет.

## §283. `PUT /api/companies/{id}` — запись ссылок и окна переноса

Доступ — как сегодня (`CanManageCompany`: владелец компании или SuperAdmin), `[RequiresOwnerTerms]`
как сегодня. **Это единственный путь записи** этих трёх полей: ни `POST /api/companies`, ни
`PUT /api/admin/companies/{id}` их не принимают (`ARCHITECTURE_CYCLE15.md` §253.4).

Тело — существующий `UpdateCompanyDto` плюс три поля:

```jsonc
{
  "yandexMapsUrl": "https://yandex.ru/maps/...",  // строка = сохранить; "" = ОЧИСТИТЬ; null/отсутствует = не трогать
  "twoGisUrl": "",                                 // ← так поле очищается
  "clientRescheduleMinHours": 4                    // null/отсутствует = не трогать; вне [0,168] = 400
}
```

**Семантика трёх состояний** (важно для фронта):

| Что прислали | Что делает сервер |
|---|---|
| поле отсутствует **или** `null` | значение не трогает (общая конвенция `UpdateCompanyDto`) |
| `""` или строка из пробелов | **очищает** поле (`NULL` в БД) — обратимая настройка |
| непустая строка | валидирует (§284) и сохраняет **как есть**, байт в байт |

Ответ **200** — полный `CompanyDto` с уже применёнными значениями (как сегодня).

### Новые 400 (голая строка, `text/plain`)

| Текст | Когда |
|---|---|
| `Ссылка должна начинаться с https://` | схема не `https` (в т.ч. `javascript:`, `data:`, `http:`) |
| `Ждём ссылку на Яндекс Карты — например, https://yandex.ru/maps/org/.../...` | домен не принадлежит Яндекс Картам |
| `Ждём ссылку на 2ГИС — например, https://2gis.ru/barnaul/firm/...` | домен не принадлежит 2ГИС |
| `Ссылка слишком длинная — не больше 500 символов` | длина > 500 после обрезки пробелов |
| `Окно переноса — от 0 до 168 часов` | `clientRescheduleMinHours` вне диапазона |

Сообщение обязано быть показано **рядом с тем полем**, которое его вызвало (доступность: связь
программная, не только цветом). Если оба поля ссылок невалидны — сервер отвечает **первым** отказом
(по порядку `yandexMapsUrl`, `twoGisUrl`); интерфейс не должен предполагать список ошибок.

## §284. Правило «принадлежности домена» — в точности

Проверяет **сервер**, форма не является защитой.

```
https, и только https
2ГИС:   host == "2gis.ru"          или host заканчивается на ".2gis.ru"
Яндекс: host == "yandex.<tld>"     или host заканчивается на ".yandex.<tld>",
        где <tld> ∈ { ru, com, com.tr, by, kz, uz, az, com.ge, ee, lv, lt, md, fr, com.am, tm, tj, kg }
запрещено: непустой user:password@, порт кроме 443, управляющие символы и пробелы внутри строки
путь, query и fragment: НЕ разбираются, НЕ нормализуются, сохраняются как прислали
```

⚠️ `*.yandex.*` из ответа заказчика читается **ограниченно** — иначе `https://yandex.evil.com/…`
прошёл бы проверку и поле стало бы открытым редиректом на публичной странице салона
(`ARCHITECTURE_CYCLE15.md` §253.3, риск R10).

**Обязаны приниматься как есть** (это тест-кейсы контракта, а не примеры):

```
https://2gis.ru/barnaul/firm/70000001094251007
https://2gis.ru/barnaul/firm/563478234628539/83.795014%2C53.330486?m=83.795954%2C53.330025%2F17.89
https://yandex.ru/maps/org/syrovarnya/11766054863/?ll=83.795110%2C53.330510&z=17
https://yandex.ru/maps/197/barnaul/?ll=83.795035%2C53.330278&mode=whatshere&whatshere%5Bpoint%5D=83.795035%2C53.330278&whatshere%5Bzoom%5D=17&z=16
```

**Обязаны отвергаться:** `http://2gis.ru/...`, `javascript:alert(1)`, `data:text/html,...`,
`2gis.ru/barnaul` (без схемы), `https://yandex.evil.com/maps`, `https://2gis.ru.evil.com/x`,
`https://clck.ru/abc`, `https://go.2gis.com/abc`, `https://user:pass@2gis.ru/x`, строка длиной 501.

## §285. Что обязан делать фронт со ссылками (правила показа)

Условия лицензии, а не оформление (перенесены из цикла 13, §205.1/§239, и покрыты тестами):

1. заполнено поле → показываем переход; пусто → **не показываем ничего**, пустых кнопок нет;
2. оба поля пусты → блока переходов нет вовсе;
3. `target="_blank"` + `rel="noopener noreferrer"` на обеих ссылках;
4. никаких логотипов и брендинга сервисов, только текст; доступные имена **ровно**
   «Открыть в Яндекс Картах» и «Открыть в 2ГИС»;
5. никакой встроенной карты и скриншота карты;
6. рядом с блоком нет слов «интеграция», «работает на», «партнёр»;
7. **`href` равен сохранённому значению байт в байт** — мы не дописываем к чужой ссылке ни `utm`,
   ни идентификаторов, ни метрик (это переформулировка пятого условия цикла 13 под новую модель).

## §286. `GET /api/bookings/client` — три вычисляемых поля `BookingDto`

Считаются **только на этом эндпоинте** (клиентский список «Мои визиты»). На всех остальных
эндпоинтах, возвращающих `BookingDto` (`/master`, `/{id}`, ответ `POST /api/bookings`), — `null`,
что означает «сервер не считал», а не «нельзя».

```jsonc
{
  // ... существующие поля BookingDto ...

  // Можно ли ПРЯМО СЕЙЧАС перенести эту запись клиентом. Считает сервер тем же набором правил,
  // который применит PATCH .../reschedule (§287): статус, AllowSelfBooking компании, онлайн-запись
  // по тарифу, окно переноса. Кнопка «Перенести» рисуется ПО ЭТОМУ ФЛАГУ, а не по локальному
  // вычислению времени в вёрстке.
  "clientRescheduleAllowed": true,

  // Окно переноса компании этой записи — чтобы объяснить пользователю, почему кнопки нет
  // («перенести можно не позже чем за 2 ч до визита»), не запрашивая компанию отдельно.
  "clientRescheduleMinHours": 2,

  // Горизонт записи компании — окно переноса рисует ровно столько дат, сколько разрешит сервер.
  // Заменяет зашитые в RescheduleModal 14 дней.
  "companyBookingHorizonDays": 90
}
```

Производительность: все три считаются **без единого дополнительного запроса на запись** — компания
уже приджойнена (`Include(b => b.Company)`), тарифы резолвятся одним батчем
(`SubscriptionResolver.GetEffectivePlansAsync` по уникальным компаниям страницы). N+1 — регресс.

⚠️ `clientRescheduleAllowed` — **подсказка интерфейсу, а не разрешение**. Сервер проверяет всё
заново в момент `PATCH`; флаг может «протухнуть» между загрузкой списка и нажатием (например,
перешагнули окно) — тогда придёт честный 400/409, и интерфейс обязан его показать.

## §287. `PATCH /api/bookings/{id}/reschedule` — главное изменение цикла

**Маршрут, метод и тело не меняются.** Второй («клиентской») ручки нет — полномочие вычисляет
сервер из базы, а не из запроса.

```jsonc
// Тело (RescheduleDto) — БЕЗ ИЗМЕНЕНИЙ. Ни одного нового поля: клиент физически не может
// попросить послабление персонала.
{ "date": "2026-10-02", "startTime": "14:00:00" }
```

Ответ успеха — **204 No Content**, как сегодня.

### §287.1. Кто теперь допускается

| Полномочие | Кто это | Правила |
|---|---|---|
| **Staff** | назначенный мастер, владелец компании записи, SuperAdmin | **ровно как сегодня**: любое свободное время, без графика, перерывов и сетки |
| **ClientOwner** | `booking.clientId` == вызывающий (и он не Staff) | **новые, строгие** правила §287.2 |
| нет | все остальные | **404, пустое тело** |

### §287.2. Клиентские правила — что проверяет сервер, в этом порядке

| № | Проверка | Отказ |
|---|---|---|
| 1 | запись существует и принадлежит вызывающему | **404** (пустое тело) |
| 2 | статус — `Pending` или `Confirmed` | **400** `Перенести можно только предстоящую запись` |
| 3 | `company.allowSelfBooking` включена | **403** (пустое тело) |
| 4 | тариф компании разрешает онлайн-запись | **402** `Online booking requires a paid subscription.` |
| 5 | до **текущего** визита осталось ≥ `clientRescheduleMinHours` | **400** `Перенести запись можно не позже чем за N ч до визита` |
| 6 | до **нового** времени тоже ≥ `clientRescheduleMinHours` | **400** (тот же текст) |
| 7 | новая дата в пределах `company.bookingHorizonDays` | **400** `Записаться можно не дальше чем на N дней вперёд` |
| 8 | новое время **есть в штатной сетке** мастера на эту дату | **409** `Time slot is no longer available` |
| 9 | не в прошлом и не через полночь | **409** `Time slot is no longer available` |
| 10 | слот не занят чужой записью (проверяется под advisory-lock) | **409** `Time slot is no longer available` |

Пункт 8 — это и есть «клиенту достаются ровно те слоты, в которые он мог бы записаться сам»:
сервер спрашивает **тот же** `SlotService` с `ScheduleFallback.None` и `excludeBookingId = {id}`.
Параметров `manual`/`extendedHours` у этого эндпоинта нет и не будет.

Пункты 5 и 6 — **оба конца** правила. Без шестого клиент за трое суток до визита перенёс бы его на
«через 20 минут».

### §287.3. ⚠️ ЛОМАЮЩЕЕ ИЗМЕНЕНИЕ № 1 — 403 становится 404

Сегодня посторонний авторизованный вызывающий получает **403** на чужую запись и **404** на
несуществующую, то есть эндпоинт подтверждает существование записи по идентификатору.
**Теперь оба случая — 404 с пустым телом.**

Тот же приём уже применён к журналу записи (`GET /api/bookings/{id}/history`, цикл 10) — это
выравнивание по существующему правилу, а не новая идея. Задевает **функциональные тесты**,
утверждающие 403; фронтенд — нет.

То же самое изменение — у `GET /api/bookings/slots?excludeBookingId=…` (§290).

### §287.4. Что переносится

**Только `date` и `startTime`.** `endTime` пересчитывается сервером из суммы длительностей услуг
визита. Мастер, услуги и компания **не меняются** — смена любого из них это отмена + новая запись
(0-bis П6). Гостевая (неавторизованная) запись клиентом не переносится: у неё нет `clientId`,
полномочие `ClientOwner` не возникает, ответ — 404.

### §287.5. Побочные эффекты успешного переноса (не меняются, кроме одного)

- `BookingEvent` вида `Rescheduled` с актором и парой «было → стало» — **как сегодня**; при
  переносе клиентом актор имеет `kind: "Client"`;
- напоминание клиенту перепланируется на новое время, старое отменяется — **как сегодня**;
- клиенту ставится сообщение `BookingRescheduled` — **как сегодня**;
- **новое:** при переносе **клиентом** мастеру ставится push-строка нового типа
  `StaffBookingRescheduled` (доставка включается рубильником `Notifications:StaffPush`, в проде
  сегодня `logging` — строка ложится в очередь). При переносе персоналом push не ставится.

### §287.6. Лимит

Тринадцатая именованная политика — **`booking-reschedule`, 30 запросов в час на пользователя**
(`RateLimits:booking-reschedule:PermitLimit|WindowMinutes`). Превышение — **429**, тело — голая
строка (`text/plain`), как у остальных политик.

## §288. `PUT /api/admin/plans/{id}` — форма не меняется, добавляется один 409

**Семантика полей остаётся ровно сегодняшней** (и это главное, что контракт здесь фиксирует):

| Поле | Тип в теле | Смысл |
|---|---|---|
| `isPublic` | `boolean \| null` | прислали — применить; `null`/отсутствует — **оставить как есть** |
| `sortOrder` | `integer \| null` | то же |
| `isActive` | `boolean` (не nullable) | применяется всегда; деактивация тарифа с активными подписчиками — **409**, как сегодня |
| `isSystemFree` | **отсутствует в теле** | меняется только `PUT /api/admin/plans/{id}/system-free` |

**Дефект, который чинит цикл, — на фронте:** `PlansTab.formToPayload()` шлёт `isActive: true`,
`isPublic: true`, `sortOrder: 0` константами при каждом сохранении (`PlansTab.tsx:148-167`).
Форма обязана отправлять **то, что видит оператор**: три поля становятся видимыми
(«Показывать на витрине», «Активен», «Порядок сортировки») и для существующего тарифа открываются
в **текущих** значениях.

### Новый 409

```
409  Системный бесплатный тариф нельзя убрать с витрины.
```

Возникает **только на переходе** `isPublic: true → false` у тарифа с `isSystemFree: true`.
У системного тарифа, который уже скрыт (поставляемый сид именно такой), сохранение с
`isPublic: false` проходит как раньше — иначе его нельзя было бы редактировать вовсе.

### Состояния тарифа, которые обязан различать интерфейс

| `isActive` | `isPublic` | Подпись в админском списке | Что это значит |
|---|---|---|---|
| `true` | `true` | **На витрине** | продаётся на `/pricing` |
| `true` | `false` | **Скрыт с витрины** | «устаревший»: с `/pricing` пропал, существующие подписчики живут и продлеваются, назначить может только суперадмин руками |
| `false` | любое | **Архивный** | назначить нельзя никому |

Подпись обязана быть видна **в списке**, без открытия формы (0-bis П3). `GET /api/admin/plans`
уже отдаёт `isPublic`, `isActive`, `isSystemFree`, `sortOrder` — новых полей не нужно.

**Что скрытие тарифа НЕ меняет** (проверяется приёмкой, а не доверием): лимиты и опции компаний на
нём, онлайн-запись, показ в каталоге, `/billing` владельца (никакой надписи «тариф устарел» ему не
показывается), продление подписки суперадмином, видимость тарифа в окне назначения подписки (оно
фильтрует по `isActive`). Единственное место, которое читает `isPublic`, — публичная витрина
`GET /api/pricing`.

## §289. `GET /api/legal/texts/BookingNotice` — форма прежняя, содержимое новое

Ответ **не меняется по форме**: `{ key, version, isDraft, contentHtml }`, `Cache-Control: public,
max-age=300` — как сегодня.

Что меняется внутри `contentHtml` (правит **только** `legal-counsel`):

1. из «Короткой строки» уходит мёртвый `<span>Подробнее</span>` — раскрывающийся элемент живёт в
   интерфейсе (`<summary>`), а не в тексте;
2. литерал `«Название компании»` заменяется **разметкой времени показа**:

```html
<span data-legal-when="companyName">компании «<span data-legal-value="companyName"></span>»</span>
<span data-legal-unless="companyName">компании, в которую вы записываетесь,</span>
```

3. `version` документа **поднимается** (изменение редакционное: состав данных, цели, получатели и
   основания не меняются → повторного согласия не требуется, гейта 451 у `uiTexts` нет).

### Что обязан делать фронт

- подставить значение **при рендере**, экранировав `&`, `<`, `>`, `"`, `'` (текст выводится через
  `dangerouslySetInnerHTML`);
- применить подстановку к **обеим** секциям — «Короткая строка» и «Полный текст»;
- **не** класть подставленный текст в кеш `useLegalText` (в кеше лежит текст без подстановки) —
  иначе два салона подряд в одной сессии могут получить название друг друга;
- имя значения — ровно `companyName`; неизвестное имя фронт оставляет как есть, а сборка
  (`ServiceBooking.LegalKit check`) на нём краснеет.

⚠️ **Фигурных скобок здесь нет и быть не должно.** `{{…}}` — это величины **времени публикации**
(их подставляет `ServiceBooking.LegalKit publish` одним значением на продукт), и любой оставшийся
`{{…}}` блокирует публикацию документа. Название компании — величина **времени показа**, поэтому у
неё принципиально другой синтаксис.

`Booking.BookingNoticeVersion` продолжает заполняться сервером при создании записи из текущей
версии текста — поведение и поле не меняются, миграции и бэкфилла нет.

## §290. `GET /api/bookings/slots` — допуск клиента-владельца записи

Параметры и ответ **не меняются**. Меняется только правило доступа на ветке `excludeBookingId`:

| Вызывающий | Было | Стало |
|---|---|---|
| персонал, который может управлять записью | 200, сетка по `manual`/`extendedHours` | **без изменений** |
| **клиент — владелец этой записи** | **403** | **200, штатная сетка**: график мастера, перерывы, шаг сетки, без собственного интервала |
| посторонний | 403 | **404** (§287.3) |
| пара `companyId`/`masterId` не совпала с записью | 400 | **без изменений** |

Для клиента `manual` и `extendedHours` **игнорируются сервером** (он не является персоналом этой
компании) — это уже сегодняшнее поведение `GetSlots`, контракт лишь фиксирует его как гарантию.
Интерфейс клиента эти параметры **не передаёт вовсе**.

## §291. Что обязан проверить фронт (чек-лист интеграции)

1. **Карточка компании:** ни одного нового запроса — обе ссылки и окно переноса приходят в том же
   `GET /api/companies/{slug}`.
2. **Порядок контактов:** телефон → адрес и переходы в карты → почта; телефон — `tel:` с номером
   только из цифр и `+`; видимое написание номера не меняется; зона нажатия ≥ 44 px.
3. **Пустые поля ссылок:** ничего не рисуется (ни серой кнопки, ни «ссылка не указана»).
4. **Форма владельца:** ошибки валидации ссылок приходят с сервера и показываются у поля;
   пустая строка = очистка, и это обратимо.
5. **Тарифы:** форма отправляет то, что видит оператор; подпись состояния видна в списке; 409 по
   системному тарифу показывается текстом сервера.
6. **«Мои визиты»:** кнопка «Перенести» — по `clientRescheduleAllowed`, а не по вычислению времени
   в вёрстке; после успеха инвалидируются `client-bookings` **и** `master-bookings`.
7. **Окно переноса клиента:** нет переключателя «Показать остальные часы»; в заголовке — салон,
   мастер и услуга (не собственное имя клиента); даты ограничены `companyBookingHorizonDays`.
8. **Ошибки переноса** показываются текстом сервера (тела 400/402/409 — голые строки), а не
   фиксированным «Время уже занято».
9. **Старый сервер** (полей нет) не ломает экраны: карты не показываются, кнопки «Перенести» нет.
