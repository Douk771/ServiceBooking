# Замер p95 публичного каталога «Домов» (цикл 39, US-39-23, DO-39-04)

Цель: p95 `GET /api/stays/public/catalog` на 500 опубликованных домах укладывается в бюджет (по умолчанию 500 мс; уточнить по SPEC цикла 39).

Статус: скрипт замера готов, **прогон не выполнен** (нужен стенд с данными; на боевой машине не запускать — она же стенд и бой, там реальные данные).
Сидирование 500 домов в репозиторий не добавлено: оно идёт через owner-API (компания -> дом -> публикация) или прямым SQL по схеме
`Cycle37Stays`/`Cycle39StaysServices`, и привязано к актуальным сущностям, которые правят параллельно. Образец сидирования — `tools/bench/cycle22/seed.py`
(фаза A через API, фаза B COPY).

Порядок:
1. Изолированный стенд: `COMPOSE_PROJECT_NAME=cycle-039 docker compose up -d` с отдельной БД (не боевой), API на свободном порту.
2. Завести 500 опубликованных домов (несколько компаний, по 5-10 домов, разные цены/вместимость, часть с бронями на будущие даты).
3. `pip install requests && python3 tools/bench/cycle39/bench_catalog.py --base http://127.0.0.1:<порт>`
4. Приложить вывод (p50/p95/max по 4 сценариям) к отчёту цикла; при превышении бюджета — `EXPLAIN (ANALYZE, BUFFERS)` запроса каталога.

Рейт-лимиты анонимного чтения на стенде могут дать 429 — поднять лимит переменными `RateLimits__...` как в `tools/bench/cycle22/run-api.sh`.
