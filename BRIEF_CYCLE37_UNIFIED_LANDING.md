# Бриф цикла 37 — единый шаблон главной страницы сервисов

Ветка: `cycle/037-unified-landing-template`. Заказчик: владелец продукта (решения 08.10.2026).

## Что хочет заказчик (дословно по смыслу)

Сейчас два сервиса — «Запись» (ezbook, `frontend/src`) и «Заказы» (goods, `frontend/goods`). Следом идут «Дома», затем «Бани». У каждого свой фронт, но главные страницы состоят из одинаковых блоков. Главная «Заказов» (`goods/src/pages/CatalogHomePage.tsx` + `BuyersBlock` + `BusinessBlock`) сделана лучше — **берём её за основу**.

Нужно:
1. **Единый шаблон главной** — общий компонент(ы) в общем коде. Правка шаблона исправляет все сервисы сразу. Содержимое у каждого сервиса своё, расположение блоков и стиль — одни.
2. **Перевести «Запись» на шаблон** (сейчас `src/pages/HomePage.tsx`, 291 строка, блоки: hero → how → PricingTeaser → компании → футер).
3. **Перевести «Заказы» на шаблон** (поведение и тесты каталога не ломать).
4. **FAQ во всех сервисах** — сейчас нигде нет.
5. **Тарифы в «Заказах»** — у «Записи» есть (`PricingTeaser`, `/pricing`, `GET /api/pricing`), у «Заказов» нет.
6. Дальнейшие сервисы (Дома, Бани) будут делаться по шаблону — шаблон должен подключаться «данными», без копирования разметки.

## Словарь заказчика → что это значит

| Слово | Значение в цикле |
|---|---|
| «шаблон» | набор общих React-компонентов + типизированный конфиг секций; НЕ генератор кода и НЕ отдельный пакет/репозиторий |
| «главная страница» | публичная страница `/` сервиса: hero, список/каталог, «для клиентов», «для бизнеса», шаги, тарифы, FAQ, футер |
| «блоки расположены одинаково» | порядок секций, отступы, типографика, ширины — задаются шаблоном; сервис не переопределяет вёрстку |
| «содержимое уникальное» | тексты, иконки, скриншоты, шаги, преимущества, FAQ, данные списка — передаются сервисом |
| «faq» | блок вопрос-ответ (раскрывающиеся пункты, доступный с клавиатуры), 6–8 вопросов на сервис, тексты — черновики, правит заказчик |
| «тарифы в заказах» | публичная сетка платных тарифов линейки «Заказы» на главной и странице `/pricing` goods, как у «Записи» |

## Решения заказчика (08.10.2026)

- **Тарифы «Заказов»: придумать платные тарифы.** Это требует бэкенда: каталог тарифов линейки Orders, публичный `GET`-эндпоинт сетки (аналог `/api/pricing`, но для линейки Orders), лимиты (`MaxOrdersPerMonth`, `MaxShops/MaxCompanies`, `MaxEmployees`, `MaxProductsPerShop`, каналы уведомлений). Сейчас в БД только бесплатный тариф `OrdersFreePlan.SeedId` и скрытый служебный «Демо» (`ShowcaseCatalog.OrdersShowcasePlanId`, `IsPublic=false`) — его в публичной сетке показывать нельзя. Образец — `ZapisTariffCatalog` и тарифы «Записи». Названия/цены/лимиты — предложить в SPEC как **черновик, помеченный «на утверждение заказчиком»**; значения вынести в сид/конфиг, чтобы менять без правок фронта. Применение платных тарифов к реальному биллингу (оплата) — вне цикла, если оно ещё не существует для Orders: сначала выяснить по коду, как «Запись» это делает, и не выдумывать.
- **FAQ: черновики пишем мы**, по 6–8 вопросов на сервис, исходя из того, что реально умеет продукт (сверять по коду/CURRENT_STATE.md, не выдумывать функций, цен, сроков, юридических обещаний). Данные FAQ лежат в коде сервиса (не в БД), структура — массив `{question, answer}`.
- Полный цикл с веткой и вливанием в `develop` в конце.

## Границы

- Не трогать кабинеты, бронирование, заказ, биллинг-страницы и юридические страницы, кроме того, что нужно для тарифов.
- Не ломать общие файлы: `frontend/goods-shared-sources.js` — список ezbook-источников, которые импортирует goods (ESLint + Tailwind content + guard-тест). Общий шаблон должен лежать в `frontend/src/components/**` (эти директории уже в списке), чтобы goods мог его импортировать без изменения правил; страницы `src/pages/*` goods импортировать нельзя.
- Сохранить `id`-якоря и aria-метки, на которые опираются существующие тесты (`#shop-list`, `buyers-title`, `data-testid="catalog-list"` и т.д.), либо обновить тесты осознанно.
- Демо-режимы (demo.visit, demo.zakaz) и витринные бейджи должны работать как раньше.
- Тексты на русском, бренд: EZBOOK Запись / EZBOOK Заказы.
