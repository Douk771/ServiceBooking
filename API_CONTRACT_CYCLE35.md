# API_CONTRACT — цикл 35 ServiceBooking: демо-стенд «EZBOOK Заказы» (`demo.zakaz.ezbook.ru`)

**Разделы §35.20–§35.29.** Решения — `ARCHITECTURE_CYCLE35.md` §35.0–§35.19. **Источник истины по форме** —
`contracts/cycle35/openapi.yaml`: при расхождении по форме прав он, по текстам и порядку проверок — этот файл.

Конвенции проекта без изменений: camelCase, enum — строкой, DateTime — ISO-8601 UTC. 400/409/429 — голая строка
по-русски (`text/plain`). 401/403 — пустое тело, **кроме** `DemoRestricted` (цикл 28). 404 — пустое тело.

Схема — **дельта**: описаны только маршруты, у которых в цикле 35 меняется форма или поведение. Всё прочее —
контракты прежних циклов (`/api/demo/*` цикла 28 заменяется этим описанием целиком).

## §35.21. `GET /api/demo/status`

Анонимный. Только демо-режим (`[DemoOnly]`).

**Query.** `product` — необязательный, без учёта регистра:

| Значение | Роли в ответе |
|---|---|
| нет / пустая строка / `services` | `owner`, `master`, `client` — ровно как в цикле 28 |
| `orders` | `shop-owner`, `shop-staff`, `shop-customer` |
| любое другое | **400** `text/plain`: «Параметр product должен быть services или orders.» |

**Порядок проверок:** демо-режим выключен → 404 без тела (до разбора параметра) → `product` → 200.

Во время сброса маршрут **не** отвечает 503: `200` с `resetting: true`. Middleware обслуживания пропускает путь
`/api/demo/status` независимо от query.

**200 `DemoStatusDto`:**

| Поле | Тип | Смысл |
|---|---|---|
| `demoMode` | bool | всегда `true` |
| `resetting` | bool | идёт сброс → фронт показывает «Демо обновляется» |
| `resetLocalTime` | `"HH:mm"` | время ночного сброса (`04:00`) |
| `timeZoneId` | string | `Europe/Moscow` |
| `lastResetAtUtc` | date-time \| null | `null` до первого сброса |
| `roles` | `DemoRoleDto[3]` | роли **запрошенного** продукта, в порядке: владелец, сотрудник, клиент/покупатель |
| `siteUrls` 🆕 | `{ services, orders }` | базовые адреса обоих демо-сайтов без завершающего `/` (из `PublicSites`): `https://demo.visit.ezbook.ru`, `https://demo.zakaz.ezbook.ru`. Фронт берёт отсюда ссылку на соседнее демо (US-35-10) |

`DemoRoleDto`: `{ role: DemoRole, label: string }` — форма цикла 28.

| `role` | `label` |
|---|---|
| `owner` | «Войти как владелец салона» |
| `master` | «Войти как мастер» |
| `client` | «Войти как клиент» |
| `shop-owner` | «Войти как владелец магазина» |
| `shop-staff` | «Войти как сотрудник магазина» |
| `shop-customer` | «Войти как покупатель» |

**Что шлёт фронт.** ezbook — без параметра (запрос не отличается от цикла 28). goods — `?product=orders`. Продукт фронт
берёт из `DemoProductProvider`, а не из адреса страницы.

## §35.22. `POST /api/demo/login`

Анонимный, `[DemoOnly]`, лимит `demo-login` (30/мин на IP).

**Тело:** `{ "role": DemoRole }`. Имена ролей уникальны для всех продуктов, параметра продукта нет. Вход под ролью
«Записи» на `demo.zakaz` технически возможен, но фронт goods таких кнопок не показывает.

**Порядок проверок и ответы:**

| # | Условие | Ответ |
|---|---|---|
| 1 | не демо | 404 без тела |
| 2 | лимит частоты | 429 `text/plain` |
| 3 | идёт сброс | 503 `DemoResetting` |
| 4 | роль неизвестна (в том числе пустая) | 400 `text/plain` «Неизвестная демо-роль.» |
| 5 | учётки роли нет или она не витринная (первый запуск; сброс ещё не создал магазины после выката цикла 35) | 409 `text/plain` «Демо-данные ещё не созданы. Зайдите чуть позже.» |
| 6 | ок | 200 `AuthResponseDto` (форма `POST /api/auth/login`) |

**Токен:** claim `sb_demo = 1`; текущие версии `Privacy` и `TermsClient`; версия `TermsOwner` — у `owner` **и
`shop-owner`**. Поэтому владелец магазина не получает 451 от `[RequiresOwnerTerms]`. Записей в журнал согласий нет.
Токен, выданный до ночного сброса, после сброса продолжает работать: Id и штамп безопасности учётки стабильны.

**Куда фронт ведёт после входа** (контракт фронта, сервер это не проверяет):

| Роль | Путь |
|---|---|
| `owner` / `master` / `client` | `/cabinet` / `/my-bookings` / `/my-visits` (как в цикле 28) |
| `shop-owner` / `shop-staff` | `/cabinet` (goods) |
| `shop-customer` | `/orders` (goods) |

**Что умеют роли «Заказов»** (права продукта, ничего нового):
- `shop-owner` — владелец кофейни: доска, каталог, меню, часы, настройки, сотрудники, история, сводка, лист сборки,
  покупатели, «Ваша подписка» (служебный тариф «Демо»);
- `shop-staff` — сотрудник кофейни (роль продукта «Сотрудник»): доска и действия с заказами, «закончилось», остатки;
- `shop-customer` — «Мои заказы» (`GET /api/orders/my`): сегодня активный в кофейне, завтра предзаказ в пекарне,
  5–10 завершённых за 30 дней, один отменён.

## §35.23. Запреты для демо-ролей в «Заказах»

Механизм цикла 28 (`API_CONTRACT_CYCLE28.md` §599). Кто считается демо-ролью: токен с `sb_demo = 1` **или** токен одной
из шести демо-учёток (выданный заново без claim).

**403 `DemoRestricted`:** `text/plain; charset=utf-8`, тело «В демо-версии это действие недоступно.», заголовок
`X-Demo-Restricted: 1`. Отказ приходит **после** авторизации (аноним получает 401) и **до** привязки модели (кривое тело
не превращается в 400).

| Маршрут | Новый запрет |
|---|---|
| `PUT /api/shops/{shopId}/slug` | смена адреса магазина |
| `DELETE /api/Companies/{id}/members/{memberId}` | удаление сотрудника — любого, в любой компании (и салона, и магазина) |
| `POST /api/staff-max/link-sessions` | подключение MAX сотруднику |

Уже действующие запреты цикла 28 — `change-password`, `change-phone`, `delete-account`, `billing/subscription/request`
(обе линии тарифов), `billing/trial`, перенос компании, смена владельца — на `demo.zakaz` работают так же.

**Не запрещено** (посетитель может менять, ночью всё возвращается): каталог, цены, фото, меню, часы, особые дни, пауза и
стоп приёма, режим покупателя, показ в каталоге, реквизиты продавца, отклонение и отмена заказов, создание своего
магазина зарегистрированным посетителем. Зарегистрированный посетитель (не демо-роль) не ограничен ничем из списка.

**Фронт goods:** 403 с заголовком `X-Demo-Restricted` → показать тело (или запасной текст
`DEMO_RESTRICTED_FALLBACK`, если тело пусто). Любой другой 403 — прежний текст «Недостаточно прав для этого действия.».

## §35.24. Обслуживание и noindex на `demo.zakaz`

Без изменения формы (цикл 28, §600a):
- во время сброса любой `/api/*`, кроме `/api/health/*` и `GET /api/demo/status`, отвечает 503 `text/plain` «Демо
  обновляется, зайдите через минуту» с `Retry-After: 60` и `X-Demo-Resetting: 1`. Оба хоста получают его одинаково;
- в демо-режиме у всех ответов API есть `X-Robots-Tag: noindex, nofollow`. nginx `demo.zakaz` ставит тот же заголовок
  на статику и отдаёт `robots.txt` с `Disallow: /`.

Фронт goods: 503 + `X-Demo-Resetting` или `status.resetting = true` → всё приложение заменяется экраном «Демо
обновляется» (`DemoMaintenanceScreen`, опрос статуса раз в 15 с). После сброса страница восстанавливается сама или по
кнопке.

## §35.25. Абсолютные адреса на демо (поведение, не форма)

Все абсолютные адреса строит `PublicSiteLinks` из конфигурации. На демо:

| Поле / место | Значение на демо |
|---|---|
| адрес магазина (`ShopManageDto.publicUrl`, QR `GET /api/shops/{id}/qr`, `CompanyDto` магазина) | `https://demo.zakaz.ezbook.ru/<slug>` |
| страница заказа (`orderUrl` в ответах заказа и в «Моих заказах») | `https://demo.zakaz.ezbook.ru/o/<token>` |
| `GET /api/companies/kinds-summary` → `services.siteUrl` / `orders.siteUrl` | `https://demo.visit.ezbook.ru` / `https://demo.zakaz.ezbook.ru` |
| `GET /api/push/config` → `siteUrls` | те же два адреса |
| `GET /api/demo/status` → `siteUrls` | те же два адреса |
| ссылки в push и сообщениях (даже неотправленных) | демо-адреса |

**Инвариант для QA:** ни одно поле ответа демо-API не содержит `https://goods.ezbook.ru` и `https://ezbook.ru`. Правовые
документы на `demo.zakaz` — локальные маршруты (`/privacy`, `/terms`, …) с данными демо-API.

**Известное исключение (долг C35-1):** 11 надписей показывают боевой домен **текстом** (например, «Каталог
goods.ezbook.ru» или `CatalogListingDto` «Магазин виден в каталоге goods.ezbook.ru»). Ссылки за ними верные.

## §35.26. Команды оператора (вывод — контракт для devops и QA)

**`ops demo reset`** (план, без `--yes`) — строки по порядку:

```
ops demo reset — профиль demo, сегодня YYYY-MM-DD
будет очищено таблиц: N (кроме справочников: города, роли, тарифы, настройки платформы), и файловые хранилища демо
будет создано: companies=14 users=… billingAccounts=… services=… bookings=… bookingEvents=… photos=… files=… reviews=… clientNotes=…
будет создано (Заказы): shops=5 categories=… products=… productImages=… dailyMenus=… specialDays=… orders=… orderItems=… orderEvents=… customerNotes=…
режим: только показать (добавьте --yes, чтобы выполнить)
```

С `--yes` — прежняя строка `выполнено: …` и за ней `выполнено (Заказы): shops=5 …` с теми же ключами. Коды выхода
прежние: 0, 1, 2 (не демо), 4 (замок занят). Числа `companies`/`users` в первой строке включают и магазины с их
людьми (магазин — это компания).

**`ops showcase plan --profile demo`** (новое) — то же содержание «будет создано» для профиля `demo` без изменения БД,
код 0. `ops showcase create|recreate|delete --profile demo` → код 2, строка «Профиль demo создаётся только сбросом демо:
ops demo reset». Без `--profile` (или `--profile prod`) — вывод цикла 28 **байт в байт**.

## §35.27. «Живая» доска демо-кофейни (поведение, не форма)

Задача `demo-board-tick`, раз в 2 минуты, только в демо-режиме. Наружу видна через обычные ответы доски, заказа и
журнала:

| Кого касается | Что происходит | Журнал (`OrderEvent`) |
|---|---|---|
| заказы, созданные генератором (`createdAtUtc` ≤ последнего сброса), в витринных магазинах, со временем получения сегодня | статус догоняет план: принят за 30–50 мин до времени получения, готов за 5–15 мин, выдан через 3–20 мин после (5 % — «Не забран» через 45 мин). Если посетитель уже изменил заказ сам, задача его не трогает | обычные события; исполнитель — демо-сотрудник кофейни (`actorKind = Staff`), время — плановое |
| (P1) заказы посетителей в витринных магазинах, у которых время получения прошло больше чем на 50 минут | `New → Rejected`, `Accepted → CancelledByShop`, `Ready → NotPickedUp` | `actorKind = System`, причина «Демо: заказ закрыт автоматически — время получения прошло.» (видна покупателю) |

Задача не создаёт заказов и уведомлений. Ревизия доски (`sinceRevision`) растёт как при любом изменении.

## §35.28. Что не меняется

- Форма всех ответов, кроме `DemoStatusDto` (+`siteUrls`) и перечня `DemoRole`.
- `GET /api/demo/status` без параметра возвращает те же роли, что в цикле 28.
- Все маршруты goods и ezbook вне демо-режима — поведение и эталон маршрутов (меняются только атрибуты трёх строк и
  параметр `product`).
- Боевой `GET /api/pricing`, тарифы «Записи», биллинг «Заказов». Служебный тариф «Демо» скрыт (`IsPublic = false`) и
  существует только в демо-БД.
- `contracts/cycle28/openapi.yaml` не правится. Для `/api/demo/*` эталоном формы становится `contracts/cycle35`.
