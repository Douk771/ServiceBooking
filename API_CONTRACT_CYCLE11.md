**Разделы §113–§119.** Читается вместе с `contracts/cycle11/openapi.yaml` (OpenAPI 3.0.3) —
**схема описывает форму, этот документ описывает смысл**. При расхождении прав YAML: из него

Архитектурные решения, объясняющие «почему так» — `ARCHITECTURE_CYCLE11.md` §102.

## §113. Что в этом цикле НЕ меняется в HTTP

Это половина контракта, и она важнее второй половины.

| Эндпоинт | Статус в цикле 11 |
|---|---|
| `GET /api/legal/documents` | форма ответа **без изменений**; меняется содержимое (`version`, `title`, `effectiveFrom` после T8) |
| `GET /api/legal/documents/{type}` | без изменений; `{type}` остаётся набором из пяти значений |
| `GET /api/legal/texts/{key}` | без изменений; ключей по-прежнему шесть |
| `GET /api/legal/consent-status` | без изменений |
| `POST /api/legal/accept` | без изменений |
| `POST /api/notification-channels` | **без изменений**: `offerAccepted.version` по-прежнему равна версии `TermsOwner`, потому что оферта D9 — приложение к нему, а не отдельный документ (`ARCHITECTURE_CYCLE11.md` §102.2) |
| `GET /api/pricing` | форма **без изменений**; меняется условие 404 (§115) |
| `GET /api/profile/consents`, `POST /api/profile/consents`, `…/revoke`, `…/revoke-preview` | без изменений |

**Ломающих изменений в цикле 11 нет.** Ни одного. Фронт, собранный до цикла, продолжает работать —
он просто не увидит новых полей и не покажет причину блокировки рубильника.

Эти эндпоинты **внесены в `contracts/cycle11/openapi.yaml` целиком**, хотя и не меняются. Причина:
цикл подменяет весь комплект текстов, и «форма ответа не изменилась» — это утверждение, которое
обязано быть проверяемым автоматически, а не на слово (`CURRENT_STATE.md` §9 L6).

## §114. `GET|PUT /api/admin/platform-settings` — новое поле и новый отказ

Доступ: `SuperAdmin`. Существующий эндпоинт цикла 7 (`API_CONTRACT_CYCLE7.md` §39).

### §114.1. Ответ: добавлено одно поле

```jsonc
// GET /api/admin/platform-settings → 200
{
  "channelPricePerMonth": null,
  "channelIdleDays": 3,
  "pricingPublicEnabled": false,
  "pricingPublicBlockedReason": "OfferIsDraft"   // ← НОВОЕ, nullable
}
```

`pricingPublicBlockedReason` — почему рубильник **нельзя** включить прямо сейчас:

| Значение | Что это значит | Что показать оператору |
|---|---|---|
| `null` | препятствий нет, включение пройдёт | тумблер активен |
| `"OfferIsDraft"` | `TermsOwner` (а с ним Приложение № 1 — оферта) в статусе черновика | тумблер выключен, подпись: «Публичные цены нельзя включить, пока оферта — черновая редакция. Опубликуйте правовые документы.» |
| `"LegalUnavailable"` | снимок правовых документов не загружен (сломан манифест на диске) | тумблер выключен, подпись: «Правовые документы временно недоступны — проверьте манифест.» |

Поле **информационное**: оно не запрещает отправить `PUT`, оно объясняет заранее, чем `PUT`
закончится. Единственный источник запрета — ответ `PUT` (§114.2).

Совместимость: добавление nullable-поля в ответ — не ломающее изменение; старый фронт его игнорирует.

### §114.2. `PUT`, включающий публичные цены при черновой оферте → **409**

```jsonc
// PUT /api/admin/platform-settings
{ "channelPricePerMonth": null, "channelIdleDays": 3, "pricingPublicEnabled": true }
```

```jsonc
// → 409 Conflict
{
  "reason": "OfferIsDraft",
  "message": "Публичные цены нельзя включить: оферта на подключение канала (Приложение № 1 к Соглашению с компанией) — черновая редакция.",
  "documentType": "TermsOwner",
  "version": "2026-09-22-draft"
}
```

Гарантии отказа:
- рубильник **не меняется**;
- строка в журнале изменений платформенных настроек **не пишется** (иначе журнал будет утверждать,
  что настройку меняли, хотя её не меняли);
- остальные поля запроса (`channelIdleDays`, `channelPricePerMonth`) **тоже не применяются** —
  запрос отвергается целиком, частично применённого `PUT` не бывает.

**409 отвечает попытка ВКЛЮЧИТЬ рубильник, а не любой `PUT` с `pricingPublicEnabled: true`.** Ровнее:
отвергается переход `false → true` при черновой оферте. Если рубильник уже включён
(`pricingPublicEnabled` в базе уже `true`) и `PUT` присылает `pricingPublicEnabled: true` повторно —
значение не меняется, и запрос **не отвергается**, даже если оферта тем временем стала черновой
(например, вернулась в черновик после отката публикации). Причина: фронтенд всегда шлёт текущее
состояние тумблера вместе с остальными полями формы, и строгая трактовка «любой `true` при черновой
оферте — 409» заблокировала бы суперадмину сохранение `channelIdleDays`/`channelPricePerMonth` в
одной форме с уже включённым тумблером, для которого ничего не просят изменить. Тумблер меняет
состояние только на переходе, поэтому только переход и проверяется.

`"reason": "LegalUnavailable"` возвращается с тем же кодом 409, когда снимок правовых документов не
загружен — тоже только на попытке включить, по той же логике. Выключение рубильника
(`pricingPublicEnabled: false`) **разрешено всегда** — запрет односторонний: закрыть витрину можно в
любой момент.

Ошибки валидации цикла 7 (`channelIdleDays` вне 0…60, отрицательная цена) остаются 400 и проверяются
**до** правовой проверки.

## §115. `GET /api/pricing` — расширилось условие 404

Форма ответа 200 и заголовки (`ETag`, `Cache-Control: public, max-age=60`, поддержка `If-None-Match`
→ 304) — без изменений, `API_CONTRACT_CYCLE7.md` §38.

**404 с пустым телом** теперь означает любое из трёх:
1. рубильник `pricing.public-enabled` выключен (как и раньше);
2. **оферта в статусе черновика** — новое;
3. снимок правовых документов недоступен — новое.

Различать их анонимному вызывающему **нельзя и не нужно**: наружу по-прежнему не должно быть видно,
существует ли каталог вообще (требование цикла 7). Фронт трактует 404 как «витрина выключена» и не
рисует ни блок на главной, ни пункт навигации — поведение `PricingPage.tsx` не меняется.

**Ещё одно следствие, не видимое в форме ответа:** из публичного каталога исключаются опции, чьё
правовое условие не выполнено (`ARCHITECTURE_CYCLE11.md` §102.10). Сегодня это ровно одна опция —
`notifications.whatsapp`. Для потребителя это выглядит как отсутствие опции в списке, а не как ошибка.

## §116. `GET /api/admin/legal/readiness` — новый эндпоинт

```
GET /api/admin/legal/readiness
Authorization: Bearer <SuperAdmin>
```

Доступ: `SuperAdmin`. **Только чтение, ничего не меняет**, безопасен на боевой машине. Не кешируется
(`Cache-Control: no-store`) — это диагностика, а не контент.

Ответ — тот же JSON, что печатает `legal status --json`, **плюс** блок `impact`, которого у CLI нет
(у него нет БД). Схема: `contracts/cycle11/legal-status.schema.json`.

```jsonc
// 200 OK
{
  "generatedAtUtc": "2026-09-23T10:15:00Z",
  "root": "/app/App_Data/legal",          // откуда приложение читает ПРЯМО СЕЙЧАС (Legal:Root)
  "ready": false,                          // можно ли публиковать
  "blockers": [                            // почему нельзя; пусто, если ready=true
    { "kind": "UnresolvedPlaceholders", "detail": "14 видов, 162 вхождений" },
    { "kind": "DraftDocuments",         "detail": "5 документов и 6 текстов интерфейса" }
  ],
  "documents": [
    {
      "type": "Privacy", "title": "Политика обработки персональных данных",
      "version": "2026-09-22-draft", "effectiveFrom": "2026-09-22",
      "isDraft": true, "changeKind": "Material", "gate": "Global",
      "file": "01-privacy-policy.html", "url": "/privacy",
      "contentHash": "4f2c…",
      "placeholders": [ { "name": "НАИМЕНОВАНИЕ_ОПЕРАТОРА", "count": 4 } ]
    }
  ],
  "uiTexts": [
    { "key": "BookingNotice", "version": "2026-09-22-draft", "isDraft": true,
      "file": "05-booking-notice.html", "contentHash": "91ab…",
      "placeholders": [ { "name": "ПОЧТА_ДЛЯ_ОБРАЩЕНИЙ", "count": 2 } ] }
  ],
  "placeholders": [                        // сводка по всему комплекту
    { "name": "НАИМЕНОВАНИЕ_ОПЕРАТОРА", "count": 14, "source": "ЕГРЮЛ",
      "files": ["01-privacy-policy.html", "02-terms-client.html"], "valuePresent": false }
  ],
  "links": { "checked": 43, "broken": [] },
  "anchors": { "missing": [] },
  "drift": {                               // артефакт образа против того, что читает приложение
    "comparedWith": "/app/App_Data/legal",
    "differentFiles": []
  },
  "impact": {                              // ТОЛЬКО у эндпоинта, у CLI этого блока нет
    "reAcceptanceRequired": [
      { "documentType": "Privacy",     "gate": "Global",     "users": 128 },
      { "documentType": "TermsClient", "gate": "Global",     "users": 128 },
      { "documentType": "TermsOwner",  "gate": "OwnerScope", "users": 11 }
    ],
    "note": "Документы с gate=None (PdnConsent, ChannelRiskNotice) никого не блокируют и в этот список не входят."
  },
  "disclaimer": "Проверено механически. Это НЕ юридическая вычитка: проверка ловит незаполненные плейсхолдеры, битые ссылки и неполный комплект, но не ловит неверный по сути текст. Публикация требует обоих подтверждений."
}
```

Правила, о которых стоит договориться явно:

- **`ready: true` не означает «можно публиковать без юриста».** Поле `disclaimer` обязательно и
  непустое **всегда**, включая `ready: true`. Фронт обязан его показывать, а не прятать за иконку.
- **`placeholders[].source`** — одно из `"ЕГРЮЛ"`, `"после уведомления РКН"`, `"решение заказчика"`,
  `"из манифеста"`. Группировка дословно из `LEGAL_REVIEW.md` §13-бис: по ней заказчик собирает
  значения, и переформулировать её на свой вкус нельзя.
- **`impact.users`** — число субъектов, у которых текущая принятая версия не равна версии в манифесте.
  Холодный запрос по `ConsentRecord`, на горячем пути его нет.
- Эндпоинт **внесён в allow-list `LegalConsentFilter`**: суперадмин, которому самому прилетел 451 из-за
  смены редакции, обязан иметь возможность посмотреть, что именно происходит.

Коды: `200`; `401` без токена; `403` не-SuperAdmin; `503` — снимок недоступен (тогда тело содержит
`ready: false` и блокер `LegalUnavailable`, а не пустоту).

## §117. Контракт CLI `ServiceBooking.LegalKit`

Это тоже контракт между людьми и машиной, поэтому он здесь, а не в README инструмента.
Вызов на машине — через одноразовый контейнер (`ARCHITECTURE_CYCLE11.md` §107.3).

### §117.1. Команды

| Команда | Что делает | Пишет на диск |
|---|---|---|
| `build` | `legal-drafts/` → `ServiceBooking.API/App_Data/legal/` | да, в артефакт |
| `check` | `build` во временный каталог + побайтовое сравнение + `links` | **нет** |
| `links` | все `href="/…"` из текстов против `contracts/cycle11/legal-routes.json` | **нет** |
| `status` | отчёт готовности (та же схема, что §116, без `impact`) | **нет** |
| `publish` | подстановка значений, снятие `-draft`, дата вступления, атомарная подмена манифеста | да, в операторский каталог |
| `rollback` | возврат предыдущего манифеста из `legal.published.json` | да, в операторский каталог |

### §117.2. Флаги

```
--source <dir>      каталог-исходник            (по умолчанию legal-drafts)
--out <dir>         каталог назначения          (build: App_Data/legal; publish: обязателен)
--root <dir>        каталог для status/links    (по умолчанию App_Data/legal)
--values <file>     legal.values.json           (publish: обязателен; status: опционален)
--version <строка>  версия публикации, без суффикса -draft
--effective-from <ГГГГ-ММ-ДД>  дата вступления в силу
--dry-run           только показать, что будет сделано; на диск не пишет
--json              машиночитаемый вывод по contracts/cycle11/legal-status.schema.json
```

`publish` без `--version`/`--effective-from` **не угадывает** значения по текущей дате: дата вступления
в силу — юридически значимое решение, и молчаливый дефолт здесь недопустим.

### §117.3. Коды возврата

| Код | Значение |
|---|---|
| `0` | успех / готово к публикации / расхождений нет |
| `1` | ошибка использования: нет файла, не разобраны аргументы |
| `3` | **артефакт разошёлся с исходником** (`check`) — этим краснеет CI |
| `4` | **не готово к публикации** (`status`): есть плейсхолдеры, черновики или битые ссылки |
| `5` | **публикация отклонена** (`publish`): не хватило значений / остался `{{…}}` / версия с `-draft` |
| `6` | **битая ссылка, потерянный якорь, или плейсхолдер в нераспознанной форме** (`links`, `check`). Третий случай — риск A4 (§112): `check` сканирует исходники на `{{…}}`, не входящий ни в одно из 14 известных имён (12 из `legal-values.schema.json` + `ВЕРСИЯ_ДОКУМЕНТА`/`ДАТА_ВСТУПЛЕНИЯ_В_СИЛУ`), и намеренно переиспользует этот же код, а не заводит седьмой — это тоже "нарушена структурная целостность источника", просто другого рода |

Каждый ненулевой код обязан печатать **список**, а не одну строку: какого значения нет, в каких файлах
оно встречается и откуда его брать. «Не готово» без перечисления причин считается дефектом команды.

### §117.4. Гарантия «ничего не меняет»

`status`, `links`, `check` и любой вызов с `--dry-run` не создают, не изменяют и не удаляют ни одного
файла в рабочем дереве и в операторском каталоге, не открывают соединение с БД и не требуют
переменных окружения. Их запуск на боевой машине безопасен — это прямое требование US-11-07.

## §119. Что фронтенд может писать, не видя кода бэкенда

1. **Экран платформенных настроек.** Тумблер публичных цен читает `pricingPublicBlockedReason`
   (§114.1) и, если он не `null`, — выключен с объяснением. На `409` при `PUT` показывается `message`
   из тела как есть (не переписанный на свой вкус: формулировка юридическая, а не UX-ная), состояние
   тумблера возвращается к серверному.
2. **Блок готовности в админке.** Только чтение, данные из `GET /api/admin/legal/readiness` по
   `legal-status.schema.json`: список блокеров, число незакрытых плейсхолдеров, сколько людей получит
   требование повторного акцепта, и `disclaimer` **видимой строкой**.
3. **Маршруты правовых страниц.** Источник — `contracts/cycle11/legal-routes.json`; тест сверяет с ним
   `App.tsx`. Ни одного нового маршрута цикл не добавляет — добавляется проверка, что существующие
   совпадают с тем, на что ссылаются тексты.
4. **Плашка черновика.** Текст меняется на честный: документы написаны не командой, а правовым
   консультантом, ожидают вычитки практикующим юристом, и **в них есть незаполненные места** —
   после T8 пользователь увидит `{{…}}` в тексте (`ARCHITECTURE_CYCLE11.md` §108.2).
5. **Заявка на канал.** Не трогается вовсе: `offerAccepted.version` = версия `TermsOwner`, как и было.
